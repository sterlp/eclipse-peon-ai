# Plan: ALLE Agenten bekommen AGENTS.md als persistentContext

## 1. Context
Aktuell bekommt nur Jon (`AiPoAgent`) `docs/memory.md` + `docs/index.md` als `persistentContext`. AGENTS.md wird als Turn-Context (UserMessage) injiziert, was Tokens verschwendet. Ziel: Alle Agenten bekommen ihre AGENTS.md (+ Agent-spezifische AGENTS-<name>.md) im System-Prompt.

## 2. Design decisions
- Neue Klasse `AgentsMdContextItem` (Eclipse-VFS basierend, wie `EclipseFileContextItem`).
- Nimmt `String agentName` und `Supplier<IProject> projectSupplier` (evaluiert zur Render-Time).
- `render()` lädt `AGENTS.md` (case-insensitive Fallback) + `AGENTS-<agentKey>.md`. Fehlt eine Datei → silently skip (kein Exception).
- `PeonAiService` zentralisiert die Zuweisung via `updateAgentPersistentContexts()`, aufgerufen in `setProject()` und bei Agent-Reload.
- Jon bekommt zusätzlich `docs/memory.md` + `docs/index.md` (bleibt wie bisher).

## 3. Affected files
- `/org.sterl.llmpeon/src/org/sterl/llmpeon/context/AgentsMdContextItem.java` — Neue Klasse.
- `/org.sterl.llmpeon.test/src/org/sterl/llmpeon/test/AgentsMdContextItemTest.java` — Test für Render-Logik.
- `/org.sterl.llmpeon/src/org/sterl/llmpeon/parts/PeonAiService.java` — `updateAgentPersistentContexts()`, Aufruf in `setProject()`.

## 4. BDD acceptance
- GIVEN Projekt mit `AGENTS.md` und `AGENTS-DEV.md`, Agent "Peon-Dev"
- WHEN `AgentsMdContextItem.render()`
- THEN Ausgabe enthält beide Dateien im Format `<path>:\n---\n<content>`

- GIVEN Projekt ohne `AGENTS.md`
- WHEN `render()`
- THEN leerer String (kein Exception)

- GIVEN `setProject()` aufgerufen
- THEN alle Agenten haben `persistentContext` gesetzt; Jon hat zusätzlich memory.md + index.md.

## 5. Rules & constraints
- `AgentsMdContextItem` muss thread-safe sein (volatile cache wie `EclipseFileContextItem`, oder einfach jedes Mal laden, da System-Prompt ohnehin gecacht ist).
- Kein Exception wenn Datei fehlt (system prompt darf nicht brechen).
