## 0. Kontext & Ziel

Agent bekommt Text aus 3 Quellen in denselben Kanal (User, Harness-Info, Tool-Results) → Tags machen Absender sichtbar
(`//-- Start <head> … //-- End <head>`) und werden zum EINZIGEN Klassifikationsschlüssel des Compact (kein instanceof).
3 Inkmente, je eigene Polarität (I1/I2 nur-additive Signatur- & Format-Änderungen, I3 nur-löschend: Caps/RenderOptions raus),
jedes für sich grün (core Surefire + OSGi PDE je nach Modultouch).

## 1. Format- & Erkennungs-Entscheidungen (I1, core)

### 1.1 `TaggedResult` (org.sterl.llmpeon.core …/agent/model/TaggedResult.java)
- `toString()` SYMMETRISCH (R-TR-1): `PREFIX + head + LN + body + LN + SUFFIX + head`
  (IST hat das End-`head` fehlt: L33 → Bug, Fix in I1).
- NEU `public static boolean isTagged(String text)` — EINE Implementierung, genutzt von
  `ChatMessageUtil` (Header-Unterdrückung) UND Compact (Drop, I3):
  ```java
  public static boolean isTagged(String text) {
      if (StringUtil.hasNoValue(text)) return false;
      int first = text.indexOf('\n');
      int last = text.lastIndexOf('\n');
      if (first < 0 || last <= first) return false;          // 1 Zeile / kein Ende
      return text.substring(0, first).startsWith(PREFIX)      // ERSTE Zeile
          && text.substring(last + 1).startsWith(SUFFIX);     // LETZTE Zeile
  }
  ```
  Zeilenweise `startsWith` (NICHT `endsWith` über Gesamttext — die End-Zeile trägt den head).
  Bewusst OHNE Head-Equal-Check (SOLL wörtlich: erste Zeile PREFIX + letzte Zeile SUFFIX).
  Accepted-Risk: User-Text, der zufällig beides trägt, gilt als Block (R-TR-2 definiert genau das Kriterium).
- `INFO` → gekürzte Doc-Fassung WÖRTLICH (Doc L131-135):
  ```
  Harness blocks (system infos, async results, tool results) look like this:
  //-- Start <head>
  <body>
  //-- End <head>
  Do not answer them as user input.
  ```
  (5 Zeilen, kein Code-Fence, keine Prosa mehr; `LN`-Join, keine trailing LN — genau wie der Block selbst.)
