## 1. Context & Ist (verifiziert)

- `AgentConfig` trägt bereits `url`/`apiKey` (Javadoc: „captured here for a later step … not yet
  applied per request") + `model`/`think`/`temperature`/`provider`. 2a aktiviert url/key und
  ergänzt `extraBody` (raw JSON String, nullable).
- Request-Pfad: `AbstractAgent.doCall` → `ToolLoopRequest{chatModel: ConfiguredChatModel,
  agentConfig}` → `ToolService.executeLoop` baut pro Iteration `ChatRequest` mit
  `agentConfig.newRequestParameters(...)` und ruft `req.call(...)` → `ToolLoopRequest.call` →
  `bridge.call(chatModel.getChatModel(), ...)` (ToolLoopRequest.java:139). **Das ist der einzige
  Model-Auflösungs-Punkt pro Request** → Wiring-Stelle für 2a.
- `ConfiguredChatModel`: geteilter `StreamingChatModel` (AtomicReference, lazy build via
  `LlmProviders.of(provider).buildModel(config)`), Rebuild bei `updateConfig`/`withModel`/
  `withThinkSupported`. Per-agent Modell läuft heute via request-level `modelName`
  (applyBase setzt `modelName` nur wenn agent.model gesetzt; sonst baked-in Base-Model).
- Provider-Interface (Zyklus 2, frisch): `LlmProvider{buildModel, newRequestParameters,
  listAiModels, listModels, supportsExtraBody(), thinkSupport()}`, Factory `LlmProviders`,
  9 stateless Singleton-Klassen. `supportsExtraBody()`: true = OpenAi, LmStudio, GithubCopilot
  (per-request), Anthropic (build-time); false = Ollama, OpenAiOfficial, Gemini, Mistral,
  GithubModels.

## 2. langchain4j-1.18.1-Fakten (aus /langchain4j-aggregator verifiziert — für Merge-Semantik maßgeblich)

1. **Kein Map-Merge existiert**: `customParameters` wird per Jackson `@JsonAnyGetter` bei der
   Serialisierung als **Top-Level-Keys (SHALLOW)** neben die Body-Felder geflatcht:
   - OpenAI: `ChatCompletionRequest.customParameters()` (…/openai/internal/chat/ChatCompletionRequest.java:254-257)
   - Anthropic: `AnthropicCreateMessageRequest.getCustomParameters()` (…/anthropic/internal/api/AnthropicCreateMessageRequest.java:219-222)
2. **Kein Reserved-Key-Schutz**: ein `model`/`messages`/`tools`-Key im customParameters-Map
   erzeugt ein **dupliziertes JSON-Key**, das im Body nach den deklarierten Feldern erscheint →
   Parser nehmen den letzten Wert → **customParameters gewinnt**. Schutz muss in unserem Code
   (→ Reserved-Keys streichen, s. §6).
3. **OpenAI (classic): per-request** `customParameters` auf `OpenAiChatRequestParameters`
   (Builder-Setter = **REPLACE**, nicht merge: OpenAiChatRequestParameters.java:274-277;
   `overrideWith` line 210 ersetzt das ganze Map).
4. **OpenAI-official (Responses API): KEIN** `customParameters` (0 Treffer im gesamten Modul).
5. **Anthropic: nur Build-time** (`AnthropicStreamingChatModel.Builder.customParameters`,
   REPLACE-Setter; kein per-request-Feld in `AnthropicChatRequestParameters`).
   `cacheSystemMessages`/`cacheTools` sind getypte Felder (wirken in den Messages, nicht
   Top-Level) → **kein Konflikt** mit User-Body-Keys.
6. **Jackson** (`jackson-databind`) liegt transitiv über `dev.langchain4j:langchain4j` auf der
   Core-Classpath → JSON-Parsing ohne neue Abhängigkeit (PO-Constraint erfüllt).

## 3. Design decisions

- **`AgentConfig` (erweitert, kein neuer Record)** — Decision + Begründung: AgentConfig trägt
  bereits url/apiKey als „later step"-Felder; ein zweiter Record wäre Indirection ohne
  Vorteil. Felder bleiben: `provider, url, apiKey, model, think, temperature` + **neu**
  `extraBody` (String, nullable). `@ToString(exclude)` um `extraBody` ergänzen (Secrets).
- **`LlmConfig` + Feld `extraBody`** (String, nullable, `@Default null`, `@ToString` exclude):
  dient als **Transport** für Build-time-Body in die effektive Build-Config
  (`AnthropicProvider.buildModel` liest `c.getExtraBody()`). `@EqualsAndHashCode` enthält es
  (Identitätsteil) — die BASE-Config trägt es nie (nur die effective Build-Config-Kopie) →
  `ConfiguredChatModel.updateConfig`-Vergleich der Base bleibt unbeeinflusst.
- **`ExtraBodyMode`** (neu, `org.sterl.llmpeon.provider`): Enum `PER_REQUEST` / `BUILD_TIME` /
  `NONE`. **Interface-Evolution:** `LlmProvider.extraBodyMode()` (pro Klasse, Werte lt.
  verifizierter Tabelle: PER_REQUEST = OpenAi, LmStudio, GithubCopilot; BUILD_TIME = Anthropic;
  NONE = Ollama, OpenAiOfficial, Gemini, Mistral, GithubModels). `supportsExtraBody()` wird
  `default boolean supportsExtraBody() { return extraBodyMode() != ExtraBodyMode.NONE; }` —
  die 9 Klassen-Overrides dafür fallen weg (Dedup), R3-Test bleibt grün (Werte identisch).
- **`ExtraBody`** (neu, `org.sterl.llmpeon.provider`, final static helper):
  `Map<String,Object> parse(String rawJson)` —
  - null/blank → `null`;
  - valides JSON-Object → Map **ohne Reserved-Keys** `model`, `messages`, `tools`
    (Top-Level-Keys werden gestrichen; Nested bleibt angetastet);
  - invalides JSON / kein Object (z. B. Array/Scalar) → **warn-Log + `null`** (PO-Entscheidung).
  - Jackson `ObjectMapper.readValue(raw, Map.class)`; `Log OR throw`: hier loggen, nie werfen.
  - Nicht-Unterstützende Provider (mode NONE) ignorieren `extraBody` schweigend (UI-Gate kommt
    in 2b) — dokumentiert im Javadoc.
- **`ConnectionIdentity`** (neu, `org.sterl.llmpeon.ai`, record):
  `(AiProvider provider, String url, String apiKey, String buildTimeBody)` — record equals/hash.
  `buildTimeBody` = extraBody **nur** bei mode BUILD_TIME, sonst `null` (PO: Key-Entität).
  Normalisierung: url/key/body als gegeben (keine Trim/Canonicalization — 1:1 Preference-Werte;
  null → `""` für Hash-Stabilität).
- **`EffectiveConnection`** (neu, `org.sterl.llmpeon.ai`, final, statische Auflösung):
  `static EffectiveConnection of(LlmConfig base, AgentConfig agent)` → record
  `(ConnectionIdentity identity, LlmConfig buildConfig, String perRequestBody, boolean isBase)`:
  - provider = `base.getProviderType()` (PO: Provider bleibt Base-Ebene);
  - url = `StringUtil.hasValue(agent.getUrl()) ? agent.getUrl() : base.getUrl()`;
  - apiKey = analog agent → base;
  - `perRequestBody` = agent.extraBody wenn mode PER_REQUEST, sonst null;
  - `buildConfig` = `base.toBuilder().url(url).apiKey(apiKey).extraBody(buildTimeBody).build()`
    (extraBody nur bei BUILD_TIME gesetzt); `isBase` = agent trägt keine eigenen url/key/body
    (→ geerbte Default-Verbindung, ADR-0034).
- **Connection-Cache in `ConfiguredChatModel`** (Decision: dort, nicht frei):
  `private final ConcurrentHashMap<ConnectionIdentity, StreamingChatModel> agentConnections`.
  - `public StreamingChatModel modelFor(AgentConfig agent)`:
    - `agent == null` oder `isBase` → `getChatModel()` (bestehender Base-Pfad, **byte-identisch**);
    - sonst `agentConnections.computeIfAbsent(identity, k -> LlmProviders.of(k.provider()).buildModel(buildConfig))`.
  - **Clear der agent-Connections** bei `updateConfig(...)` (jeder Base-Change), `withModel`
    (baked-in Base-Model ändert sich) und `withThinkSupported` (build-time Flag) — zusammen mit
    dem bestehenden `chatModel.set(null)`. Kein Eviction nötig (Schlüsselraum = Anzahl
    Agent-Configs, instanzweise billig); dokumentieren.
  - `ToolLoopRequest.call()` → `bridge.call(chatModel.modelFor(getAgentConfig()), ...)`
    (einziges Wiring, s. §1).

## 4. Per-request extra body — Merge & Konflikt-Semantik (Zyklus-2c-Übergangsregel)

**Merge-Ordnung (per-request Provider):** `finalMap = providerBerechneteEntries` (heutige
`customParameters`: OpenAI `cache_control` bei claude-Modell; LM Studio `reasoning` bei Think)
**→ User-Body-Entries darüber** (User gewinnt bei Key-Konflikt — **PO-Festlegung 2026-08-28**).
Nur wenn `finalMap` nicht leer → `b.customParameters(finalMap)`; sonst **gar nicht setzen**
(heute: kein claude/kein think ⇒ `customParameters` null ⇒ Body unverändert — bleibt so).
- `OpenAiProvider.newRequestParameters`: cache_control-Hardcode **bleibt** (2c!) + User-Body.
- `LmStudioProvider.newRequestParameters`: `reasoning`-Entry + User-Body.
- `GithubCopilotProvider.newRequestParameters`: nur User-Body (heute kein customParameters).
- `AnthropicProvider.buildModel`: `builder.customParameters(ExtraBody.parse(c.getExtraBody()))`
  wenn nicht null; `cacheSystemMessages`/`cacheTools` bleiben unangetastet (getypte Felder,
  kein Konflikt, §2.5).
- Reserved-Key-Strip passiert **einmalig** in `ExtraBody.parse` (alle Provider profitieren).
- **Beweis-Pflicht im Test:** Konfliktfall User-Body + cache_control **koexistieren**
  (beide Keys im Map, solange Keys sich nicht überschneiden).

## 6. Rules & constraints

- JUnit 5 + AssertJ, **GIVEN/WHEN/THEN**-Namen in allen neuen Tests.
- Thread-safety (Root-AGENTS): `ConcurrentHashMap` + `computeIfAbsent` (atomar, kein Double-Build);
  Provider stateless. `Log OR throw`. Keine neuen Abhängigkeiten (Jackson = transitiv vorhanden).
- **Verhaltensinvariante:** alle Pfade ohne extraBody/agent-url/agent-key byte-identisch
  (Golden-Suite `AiProviderRequestParametersTest` + bestehende 454 Tests grün).
- Reserved Keys: `model`, `messages`, `tools` — dokumentieren (provider.md/caching.md-Verweis im
  Javadoc; Doku selbst schreibt der PO).
- Build/Zyklen (PO-Festlegung 2026-08-28, Memory 19 + AGENTS.md „Build cycles & git" + po-agent-jon.md R15):
  Da Mek prüft zu Build-Start den aktuellen Branch (`git branch --show-current`) und committet
  **dort** nach JEDEM grünen Inkrement (`inc-N: <one-line>`, nur Inkrement-Dateien). Kein
  Git-Repo / kein Branch → **stopp + PO/User fragen** (kein Auto-Commit). Merge/Squash in die
  Base-Branch = Entscheidung des Users. Test-Rhythmus: `eclipseBuildProject(llmpeon-core)` +
  `eclipseRunTests` nach JEDEM Inkrement; final Root-`mvn clean verify` + Plugin-Compile-Check.
- MockLlmServer (core main) für Integrationstests verfügbar — Netzwerk-Tests nur wo nötig.

## 7. BDD-Akzeptanz (neue Tests — Namen 1:1)

**EffectiveConnectionTest** (`ai/`):
1. `effectiveConnectionInheritsBaseUntilAgentOverrides` — GIVEN Agent ohne url/key/body
   WHEN `EffectiveConnection.of(base, agent)` THEN `isBase` true AND identity == Base-Identität
   (provider/url/key identisch).
2. `effectiveConnectionUsesAgentUrlAndKey` — GIVEN Agent mit eigener url + key WHEN resolve
   THEN identity trägt Agent-Values AND provider bleibt Base-Provider.
3. `buildTimeBodyIsInIdentityOnlyForBuildTimeProviders` — GIVEN Anthropic-Agent mit extraBody
   THEN identity.buildTimeBody == body; GIVEN OpenAI-Agent mit extraBody THEN
   identity.buildTimeBody == null AND perRequestBody == body; GIVEN Gemini-Agent mit extraBody
   THEN perRequestBody == null (ignored).

**ModelConnectionCacheTest** (`ai/`, `ConfiguredChatModel`):
4. `sameEffectiveIdentityReusesConnection` — GIVEN zwei Agents mit gleicher effektiver
   Identität WHEN `modelFor` THEN dieselbe Instanz (`isSameAs`).
5. `differentIdentityBuildsSeparateConnection` — GIVEN Agents mit verschiedener url/key
   THEN verschiedene Instanzen.
6. `anthropicBodyChangesIdentityOpenAiBodyDoesNot` — GIVEN zwei Anthropic-Configs mit
   verschiedenem extraBody THEN verschiedene Instanzen; GIVEN zwei OpenAI-Configs mit
   verschiedenem extraBody THEN dieselbe Instanz.
7. `baseConnectionIsInheritedInstance` — GIVEN Agent ohne eigene url/key/body WHEN
   `modelFor` THEN `isSameAs(getChatModel())` (kein Double-Build).
8. `configUpdateClearsAgentConnections` — GIVEN gecachte Agent-Connection WHEN
   `updateConfig`/`withModel`/`withThinkSupported` THEN nächste `modelFor` baut neu
   (Instanz wechselt).

**ExtraBodyTest** (`provider/`):
9. `parseStripsReservedKeysKeepsRest` — GIVEN Body `{"model":"x","messages":[],"tools":[],"foo":1}`
   THEN Map == `{"foo":1}`.
10. `invalidJsonWarnsAndReturnsNull` — GIVEN `{invalid` THEN null (warn-Log; AssertLog nicht
    nötig — null ist der Vertrag).
11. `blankOrNonObjectJsonReturnsNull` — GIVEN `""`/`"[1]"`/`"5"` THEN null.

**ExtraBodyRequestTest** (`provider/`, per-request Injection):
12. `perRequestBodyIsInjectedIntoCustomParameters` — GIVEN OpenAI-Agent mit validem Body
    WHEN `newRequestParameters` THEN `customParameters` enthält die Body-Keys.
13. `userBodyAndCacheControlCoexist` — GIVEN claude-Modell (provider-Hardcode `cache_control`
    = `ephemeral`) + User-Body — in 2 Szenarien:
    (a) Body OHNE `cache_control`, z. B. `{"temperature2":1}` → beide Keys koexistieren
        (Hardcode `cache_control`=ephemeral + Body-Key `temperature2` im Map);
    (b) Body MIT `cache_control`=`{"type":"persistent"}` → **User-Body gewinnt**:
        `cache_control`=`persistent` (Hardcode überschrieben; PO-Festlegung 2026-08-28).
14. `noBodyLeavesCustomParametersUntouched` — GIVEN kein Body, kein claude-Modell, kein think
    THEN `customParameters()` == null (byte-identisch zu heute).
15. `invalidBodyIsIgnoredCallProceeds` — GIVEN invalides JSON WHEN `newRequestParameters`
    THEN Parameter wie ohne Body (kein throw).
16. `lmStudioReasoningAndBodyMerge` — GIVEN think gesetzt + Body THEN `reasoning`-Entry +
    Body-Keys koexistieren; bei Konflikt auf `reasoning` gewinnt User-Body (PO 2026-08-28).
17. `anthropicBuildTimeBodyAppliedAtBuild` — GIVEN Anthropic-Config mit extraBody WHEN
    `buildModel` THEN Instanz gebaut ohne throw AND (Reflexion/Verhaltenstest: Request-Body
    enthält Body-Keys — via MockLlmServer, falls praktikabel; sonst: `ExtraBody.parse`-Aufruf
    über die Build-Config + Unit-Test der Mapping) AND cacheSystemMessages/cacheTools unverändert.

**Wiring:**
18. `toolLoopUsesAgentConnection` — GIVEN Agent mit eigener url (MockLlmServer-Port A) vs.
    Base (Port B) WHEN `executeLoop` THEN Request landet beim Agent-Server (MockLlmServer
    aufrufen; falls zu schwer: `modelFor`-Selection-Test + Code-Pfad-Review — Dev-Entscheidung,
    Plan-Vermerk).
