# Plan: Provider-Refactoring (provider.md R1–R5, ADR-0033 Slice 1)

**100% verhaltenstreu**, core-only (`org.sterl.llmpeon.core`). Option B (2026-08-28): alle
Cache-Hardcodes **bleiben unverändert** in den neuen Provider-Klassen — keine Entfernung hier.

## 1. Context

`org.sterl.llmpeon.ai.AiProvider` ist ein Enum (9 Konstanten) mit je Konstante drei
Verhaltensmethoden (`buildModel` / `newRequestParameters` / `listAiModels`) plus statischen
Helpers. Ziel (provider.md): neue Komponente `org.sterl.llmpeon.provider` mit **einer Klasse
pro Provider**, gemeinsames Interface inkl. `supportsExtraBody()` (R3) und `thinkSupport()` (R5).
`AiProvider` bleibt Name-Registry/`parse` (Preference-Kompatibilität). Grund: neue Provider
(Slice 2: Ox Alpha) ohne Enum-Wachstum; Provider-Quirks gekapselt.

**Verifizierte Abbruchkanten (Aufrufstellen):**
- Plugin (`org.sterl.llmpeon` + `org.sterl.llmpeon.test`) nutzt `AiProvider` **nur** als
  Name-Registry: `.name()`, `AiProvider.parse(...)`, Konstanten, `!=`-Vergleich
  (AIChatView.java:442,483; AiConfigPreferenceView.java Combo-Labels; LlmPreferenceInitializer.java
  parse/name; PeonAiServiceTest 18× `.providerType(AiProvider.OPEN_AI)`; EclipseWriteValidatorUnitTest).
  **Kein** Plugin-Aufruf von `buildModel`/`newRequestParameters`/`listAiModels` → **Plugin wird
  NICHT angefasst** (nur Compile-Check, s. §5).
- Die drei Verhaltens-Einstiegspunkte liegen alle in core:
  - `LlmConfig.listAiModels()` / `LlmConfig.listModels()` (LlmConfig.java)
  - `ConfiguredChatModel.getChatModel()` → `config.getProviderType().buildModel(config)`
  - `AgentConfig.newRequestParameters(tools)` → `provider.newRequestParameters(this, tools)`
- `MockLlmServer` (core main) + Core-Tests: nur Konstanten, außer `AiProviderRequestParametersTest`
  (ruft `AiProvider.X.newRequestParameters(...)` direkt) und `ModelListingTest`
  (`AiProvider.OLLAMA.listModels(config)`, `@Disabled` integration).
- Statische Helper (`applyBase`, `effortFor`, `anthropicThinkingType`, `openAiOfficialParameters`,
  `MODEL_TIMEOUT`): **keine** externen Referenzen (alles private/package-intern).
- `ThinkModelMapping` ist per `AiProvider`-Enum-Namen auf Resource-Dateien
  `/thinking/OPEN_AI`, `/thinking/ANTHROPIC` getippelt; `effortFor`/`anthropicThinkingType`
  referenzieren `AiProvider.OPEN_AI`/`ANTHROPIC`. **API von ThinkModelMapping bleibt unverändert**
  (verhaltenstreu, minimaler Diff) — Provider-Klassen referenzieren die Enum-Konstanten ihrer
  Familie.
- Ist-Details, die erhalten bleiben: alle 9 Konstanten override `buildModel` + `listAiModels`;
  `newRequestParameters`-Override bei OLLAMA, OPEN_AI, OPEN_AI_OFFICIAL, LM_STUDIO, ANTHROPIC,
  GITHUB_MODELS, GITHUB_COPILOT; GOOGLE_GEMINI + MISTRAL nutzen das **Default**
  (`ChatRequestParameters.builder()` → `DefaultChatRequestParameters`, nur Base-Fields).
  Enum-Default `listAiModels` (Fallback-Wrap des konfigurierten Modells) nutzt aktuell **kein**
  Provider — bleibt aber als Interface-Default (verhaltenstreu).
- Cache-Hardcodes (Option B, UNVERÄNDERT mitnehmen):
  - ANTHROPIC `buildModel`: `defaultRequestParameters(AnthropicChatRequestParameters.builder().cacheSystemMessages(true).cacheTools(true).build())`
  - OPEN_AI `newRequestParameters`: `customParameters(Map.of("cache_control", Map.of("type","ephemeral")))` wenn Modell mit `claude` startet
  - LM_STUDIO `newRequestParameters`: `customParameters(Map.of("reasoning", ThinkResolver.toReasoning(...)))` (Think, nicht Cache — ebenfalls erhalten)
  - Alle `TODO prompt_cache_key`-Kommentare bleiben als Kommentare.

## 2. Design decisions

- **Package:** `org.sterl.llmpeon.provider` (lt. provider.md R1). `AiProvider`-Enum bleibt in
  `org.sterl.llmpeon.ai` (nicht verschieben — Plugin-Imports würden brechen).
- **Interface `LlmProvider`** (public, in `org.sterl.llmpeon.provider`):
  ```java
  public interface LlmProvider {
      StreamingChatModel buildModel(LlmConfig config);
      default List<AiModel> listAiModels(LlmConfig config);            // Fallback-Wrap (Enum-Default)
      default List<String> listModels(LlmConfig config);               // delegiert zu listAiModels (Enum-finally)
      default ChatRequestParameters newRequestParameters(AgentConfig mc, List<ToolSpecification> tools); // Base-only (Gemini/Mistral)
      boolean supportsExtraBody();
      ThinkSupport thinkSupport();
  }
  ```
  Defaults implementieren exakt das heutige Enum-Default-Verhalten (via `ProviderRequestSupport.applyBase`).
- **`ThinkSupport`** (public sealed interface, eigene Datei): 5 Records — `Boolean`,
  `Values(List<String>)`, `FreeString`, `None`, `Unknown` — plus statische Konstanten `NONE` /
  `UNKNOWN` (Records sind Singletons). Semantik (User 2026-08-28): Form des **per-agent**
  Think-Inputs, den der Provider konsumieren kann; build-time-globale Think-Achse (ADR-0003)
  gehört NICHT hinein. `UNKNOWN` = echtes Default für fremde/neue Provider (Slice 2 Ox Alpha).
- **Factory `LlmProviders`** (public final, statisch):
  `public static LlmProvider of(AiProvider provider)` — switch expression über die 9 Konstanten;
  Provider-Klassen sind **stateless Singletons** (Thread-safety-Invariante: keine Felder;
  `copilotHeaders()` liest System-Properties zur Aufrufzeit — bleibt so). Zusätzlich
  `public static List<LlmProvider> all()` (für Tests/UI, Reihenfolge = `AiProvider.values()`).
- **Gemeinsame Helper-Klasse `ProviderRequestSupport`** (public final, statisch):
  `applyBase`, `effortFor`, `anthropicThinkingType`, `openAiOfficialParameters`,
  `MODEL_TIMEOUT` (= `SharedHttpClient.MODEL_TIMEOUT`, Single Source). Signaturen 1:1 aus dem
  Enum übernehmen (Javadocs mitnehmen).
- **Provider-Klassen** (je eine Datei, public final, stateless): `OllamaProvider`,
  `OpenAiProvider`, `OpenAiOfficialProvider`, `LmStudioProvider`, `GoogleGeminiProvider`,
  `MistralProvider`, `AnthropicProvider`, `GithubModelsProvider`, `GithubCopilotProvider`.
  Code 1:1 aus den Enum-Konstanten (inkl. privater Konstanten/Helper: `MODELS_URL`,
  `ANTHROPIC_VERSION`, `DEFAULT_BASE_URL`, `CATALOG_*`, `INTEGRATION_ID`, `copilotHeaders()`,
  `baseUrl()`, Kommentare/TODOs). Gemini/Mistral override `newRequestParameters`/`listAiModels`
  nur soweit heute (Gemini: nur `listAiModels` + buildModel; Mistral analog).
- **R3 `supportsExtraBody()`** (Wertetabelle verifiziert 2026-08-28, langchain4j 1.18.1):
  - `true`: `OpenAiProvider`, `LmStudioProvider`, `GithubCopilotProvider` (per-request
    `customParameters`), `AnthropicProvider` (**Build-time** — Javadoc darauf hinweisen)
  - `false`: `OllamaProvider`, `OpenAiOfficialProvider`, `GoogleGeminiProvider`, `MistralProvider`,
    `GithubModelsProvider`
- **R5 `thinkSupport()`** (Wertetabelle, im Test fixiert):
  | Provider | thinkSupport |
  |---|---|
  | Ollama | `ThinkSupport.Boolean` |
  | OpenAi / OpenAiOfficial / GithubModels / GithubCopilot | `ThinkSupport.Values` — Werte aus `ReasoningEffort.Known` lowercased (wie `ReasoningPresets`-Konvention: `Arrays.stream(ReasoningEffort.Known.values()).map(k -> k.name().toLowerCase(Locale.ROOT)).toList()` → auto-trackt SDK) |
  | LmStudio | `ThinkSupport.FreeString` |
  | GoogleGemini | `ThinkSupport.NONE` (User 2026-08-28: verifiziert kein per-request Think) |
  | Mistral | `ThinkSupport.NONE` (ditto) |
  | Anthropic | `ThinkSupport.Values(List.of("adaptive","enabled"))` |
- **Enum nach Refactoring:** nur die 9 (leeren) Konstanten + `parse(String)` (Fallback OLLAMA,
  warn-Log) + Javadoc „Name-Registry, Verhalten über `LlmProviders.of(this)`". Keine
  Verhaltensmethoden mehr.

## 3. Architecture / Datenfluss (nach Refactoring)

```
LlmConfig.listAiModels()/listModels() ─┐
ConfiguredChatModel.getChatModel() ────┼─► LlmProviders.of(AiProvider) ─► <X>Provider
AgentConfig.newRequestParameters(tools)┘        (Singletons, stateless)
```
- `LlmConfig`/`AgentConfig` (Feldtyp `AiProvider`) bleiben unverändert (R4) — nur die 4
  Delegationszeilen (§4) ändern.
- `ThinkModelMapping`/`ThinkResolver`/`SharedHttpClient`/`AiModelParser`/`ReasoningPresets`:
  **unberührt**.
- Plugin: null.

## 5. Rules & constraints

- JUnit 5 + AssertJ, Testnamen GIVEN/WHEN/THEN (bzw. etabliertes `when_then`-Stil der Datei —
  bei **neuen** Klassen strikt GIVEN/WHEN/THEN).
- Thread-safety-Invariante (Root-AGENTS): stateless Singletons, keine mutierbaren Felder.
- Log OR throw, never both. Elegantes modernes Java (switch expression, records).
- Verhaltenstreu: Request-Byte-Stream 100% identisch (Golden-Tests = Beweismittel);
  **keine** Cache-Hardcode-Entfernung, keine `LlmConfig`/`AgentConfig`-Strukturänderungen.
- Schritt-2-Features (JSON-Body-UI, Config-Umbau, Ox Alpha, Connection-Cache): NICHT anfassen.
- `docs/` wird von diesem Refactoring NICHT geschrieben (PO/user ownership) — Status-Umbuchungen
  in provider.md sind PO-Aufgabe nach Review.
- Build/Test-Rhythmus: nach JEDEM Inkrement `eclipseBuildProject(llmpeon-core)` +
  `eclipseRunTests(llmpeon-core)` (Core = Maven, JUnit 5). Ganz am Ende zusätzlich:
  `mvn clean verify` im Repo-Root (damit Plugin/Test-Bundles den neuen Core aus der Target
  Platform holen) + Plugin-Compile-Check `mvn -o -pl org.sterl.llmpeon -am package`
  (R4-BDD `coreChangeVisibleInPlugin`).
- Keine neuen Abhängigkeiten (langchain4j/OpenAI-SDK kommen bereits über `lib/`).

## 7. Test-Strategie

- **Golden-Tests = Regressionsschranke:** `AiProviderRequestParametersTest` (alle
  `newRequestParameters`-Pfade inkl. Think-Schema, Cache-`cache_control`, LM-`reasoning`),
  `ConfiguredModelTest`, `LlmConfigTest`, `ThinkModelMappingTest` → bleiben grün, nur Fabrik-Pfade.
- **Neu:** `ProviderFactoryTest` (BDD 1, 2), `ProviderCapabilitiesTest` (BDD 3, 4 — beide
  Tabellen in einem Parameterisierungs- bzw. je-einen-`assertThat`-Block pro Provider fixiert,
  1:1 lesbar).
- `ModelListingTest`: @Disabled integration — nur Compile-Pfad anpassen; nicht ausführen.
- Plugin-Tests: keine Änderung erwartet (PeonAiServiceTest etc. nur Konstanten); werden im
  normalen PO-Zyklus mitlaufen, hier nicht angestoßen.
- Testability: Provider sind stateless → keine Mocks/Timeouts nötig; keine Netzwerk-Aufrufe in
  den neuen Unit-Tests (`listAiModels` nur im Fallback-Pfad testen, der keinen HTTP-Treib
  — HTTP-Pfade bleiben in den @Disabled-Integrationstests).
