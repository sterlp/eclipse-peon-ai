## 1. Context
Paul hat in `AbstractAgent.compactAfterTokens()` (L231-235) einen Kommentar hinterlassen: die
Compact-Trigger-Logik (compactFactor) gehört nicht in `AbstractAgent` — sie wandert zu `PoDelegateTool`
(Jon), der einen Auto-Compact der Sklaven macht, wenn diese 70 % Context verbraucht haben, **bevor** sie
einen Request bekommen.

**Befund (gemessen 2026-10-19):** `compactAfterTokens() = autoCompactAfter × compactFactor`
(Sklaven 0.7 via `BuildPoAgentComponent.SLAVE_COMPACT_FACTOR`) wird an drei Stellen benutzt:
1. Pre-Turn-Gate in `AbstractAgent.doCall` (L337-342),
2. `HandleToolLoopCompactComponent` (L42: `agent.compactAfterTokens()`, L82: `forceHint`) für **alle**
   In-Loop-Entscheidungen,
3. **nicht** in `tokenContextUsedInPercent()` — das rechnet gegen die rohe Config (AbstractAgent:219).

Folge: bei `tokenWindow=250000` bekommt der Dev den Hint bei 166 250 (66,5 % des echten Fensters) und
compactet bei 175 000; die Anzeige zeigt dabei 70 %. Zwei Skalen im selben Objekt.

**Ziel-SOLL (mit Paul abgestimmt):**

| Ort | Regel |
|---|---|
| `PoDelegateTool` (Jon) | **vor** jeder Delegation an einen Sklaven: `used > 0,7 × autoCompactAfter` → `agent.compact(monitor)`. `MIN_COMPACT_MESSAGES`-Guard + `autoCompactAfter > 0`-Gate bleiben. Faktor lebt hier. |
| `AbstractAgent` | `compactFactor` (Feld, Ctor-Param), `compactAfterTokens()` **und** das Pre-Turn-Gate in `doCall` entfallen ersatzlos — kein Agent-Wissen über „Sklave". |
| `AiAgent`-Interface | `compactAfterTokens()` entfällt (default 0 wird zurückgezogen). |
| `HandleToolLoopCompactComponent` | rechnet **nur** mit `autoCompactAfter` (rohe Config): Direkt-Compact `used > autoCompactAfter`, Hint im 95-%-Band davon. |
| `tokenContextUsedInPercent()` | unverändert rohe Config — jetzt dieselbe Skala wie die Entscheidung. |

**Bekannte Nebenwirkung, bewusst:** ein queued Follow-up an einen Sklaven läuft danach nicht mehr
durch einen Pre-Turn-Compact (heute tut er das); aufgefangen vom In-Loop-Hint.
Gleiches gilt für den Headless-Agenten (`AiDeveloperAgentTest`-Szenarien) — er compactet künftig
nur noch In-Loop (Direkt > Budget, Hint > 95 %).

## 3. Design-Entscheidungen

**D1 — Faktor wandert, Wert bleibt:** Die 0.7-Schwelle wandert von `AbstractAgent` zu
`PoDelegateTool`. Die Konstante wird in `PoDelegateTool` als `SLAVE_COMPACT_FACTOR = 0.7` neu
definiert (private static final double). `BuildPoAgentComponent.SLAVE_COMPACT_FACTOR` entfällt in
Inc 3 — kein Cross-Modul-Sharing, keine neue Abstraktion für eine einzige Konstante.

**D2 — Kein `AiAgent`-Erweiterung, kein Injection-Parameter:** `PoDelegateTool` kennt
`configuredModel` nicht. Der `autoCompactAfter`-Wert kommt aus der Schreibseite — `PoDelegateTool`
kriegt den Config-Supplier über den bestehenden Ctor injiziert (neuer Param `Supplier<Integer>`
oder `IntSupplier autoCompactAfter`, gebaut in `BuildPoAgentComponent` aus
`configuredModel.getConfig()::getAutoCompactAfter`). Begründung: live-Update-Sicherheit — der Wert
muss bei Config-Reload konsistent gelesen werden, kein Snapshot im Ctor.

**D3 — Pre-Turn-Gate entfallt für ALLE Agenten (Jon eingeschlossen):** Heute benutzt Jon
(`AiPoAgent`, kein Override von `compactAfterTokens`, IS Voll-Grep-Befund) das Pre-Turn-Gate gegen
die volle Budget-Schwelle. Nach Inc 3 compactet Jon nur noch In-Loop (Hint > 95 %, Direkt > Budget).
Das ist bewusst: Paul will den Compact nur noch als Delegations-Regel und als In-Loop-Regel — kein
Agent macht „vor dem Prompt" heimlich ein Compact mehr. Jon behält seine manuelle
`compactSession`-Möglichkeit. Im CHANGELOG erwähnen (User macht das).

**D4 — Kein Konflikt mit `MIN_COMPACT_MESSAGES`:** Der bestehende Guard bleibt scharf —
`compact()` selbst skipped bei `size < MIN_COMPACT_MESSAGES` (`AbstractAgentCompactResultTest`).
Der neue Delegations-Compact in `PoDelegateTool` ruft `slave.compact()` und vertraut dessen
Result-Status (COMPACTED / SKIPPED_SMALL / FAILED_EMPTY) — dieselbe Switch-Diskriminierung wie
`PoDelegateTool.compact(NamedAgent)` (L190-199).

**D5 — Inkrement-Struktur (jedes Inkrement grün, EINE Polarität):**
- **Inc 1 (nur hinzufügen):** Neue Delegations-Compact-Regel in `PoDelegateTool.dispatch()` — der
  alte Pre-Turn-Gate in `AbstractAgent` existiert **weiter**. Am Boundary (70 %) compacten beide
  Trigger — doppelt compacten ist harmlos (`compact()` ist idempotent, zweiter Aufruf liefert
  `SKIPPED_SMALL` wegen MIN_COMPACT_MESSAGES bzw. „schon kompakt").
- **Inc 2 (nur umstellen):** `HandleToolLoopCompactComponent` rechnet nur noch mit roher Config —
  die Stubs `agent.compactAfterTokens()` liefern exakt den Config-Wert (160000/210000), so dass die
  Tests nach der Umstellung funktional gleich bleiben (kein Mock-Edit nötig, nur Verifikation).
- **Inc 3 (nur löschen):** `compactFactor`, `compactAfterTokens()`, Pre-Turn-Gate, 3-Arg-Ctor-Kette,
  `SLAVE_COMPACT_FACTOR` — löschen + die im Inventar genannten Test-Edits.

**D6 — `tokenContextUsedInPercent()` bleibt unverändert** (rohe Config, `min(autoCompactAfter, 4000)`
- oddity bleibt wie in ADR-0021 :53-54 beschrieben). Nach Inc 3 zeigt die Anzeige dieselbe Skala wie
die Entscheidungen — das war gerade der Befund („Zwei Skalen im selben Objekt").

**Was der Code sieht (Inc 1-Snippet in `PoDelegateTool.dispatch`):**

```java
private String dispatch(NamedAgent target, String prompt, List<ContextItem> orders) {
    ArgsUtil.requireNonBlank(prompt, "prompt");
    AiAgent slave = target.agent();
    slave.setTurnContextSupplier(() -> orders);
    compactSlaveBeforeDelegation(slave);          // NEU (Inc 1)
    // ... bestehender Code unverändert
}

/** Paul: 0.7 des geteilten Budgets — vor der Delegation compacten, sonst stirbt der Task. */
private void compactSlaveBeforeDelegation(AiAgent slave) {
    var budget = autoCompactAfter.getAsInt();
    if (budget <= 0) return;                                   // R-CIB-1: 0 = off
    if (slave.getMemory().getTotalTokenUsed() <= (int) (budget * SLAVE_COMPACT_FACTOR)) return;
    var result = slave.compact(monitor);                       // R-CC-8-Status folgt aus compact()
    if (result.status() != CompactResult.Status.COMPACTED) return;
    onTool(slave.getName() + " auto-compact before delegation: " + result.resultLine());
}
```

**Inc 2-Snippet (Budget in `HandleToolLoopCompactComponent.handle`):**

```java
// ALT:
var budget = agent != null ? agent.compactAfterTokens() : req.getConfig().getAutoCompactAfter();
// NEU (rohe Config, immer):
var budget = req.getConfig().getAutoCompactAfter();
```

## 7. BDD-Akzeptanz (Messbar)
