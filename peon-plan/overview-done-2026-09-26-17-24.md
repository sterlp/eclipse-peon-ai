## 2. Design-Entscheidungen

1. **R-CC-11 Rename/Move (Inkrement 1, rein mechanisch):** `CompactEngine`→**`CompactService`**, `CompactStager`→**`ContextTrimComponent`** (beide bleiben im `org.sterl.llmpeon.compact`-Package), Test-Klassen mitumbenannt (`CompactServiceTest`, `ContextTrimComponentTest`). `CompactResult` (+nested Status/Stage/Stats) wandert ins neue **`org.sterl.llmpeon.model`** (Q1 bestätigt, Jon 2026-09-26; `tool.model` = Tool-Loop-Domain, fehlender Schnitt). Clean Break: alte Namen weg, **keine** Aliase/Deprecateds. `CompactLog` + **eine** Info-Kommentarzeile (Zweck: Test-Naht — capturing-Impl statt Log-Capture-Lib für „genau EIN debug-Log“ + Result-Level-BDDs). `CompactConstants` unverändert (e). Javadoc-`{@link}`-Referenzen (c: AiAgent, AiAgentStatusModel, ToolLoopRequest) im selben Inkrement mitziehen.
2. **R-CC-12 — `requestTokens` + `requestIsEstimate` (Q2 bestätigt: **B′**, Jon 2026-09-26):**
   `Stats` +2 Komponenten: `requestTokens` (Integer) + `requestIsEstimate` (boolean).
   **B′:** `requestTokens` = **nur** `memory.getLastProviderInputTokens()` (Provider-Wert, per
   Konstruktion echt — nie `totalTokenUsed`); `null` → `requestIsEstimate=true`, `resultLine()`
   zeigt `request n/a (no provider value)`. Bei Provider-Wert: `requestIsEstimate=false`,
   `request 80211 (provider)`. Begründung: SOLL-Wortlaut „Nur echte Provider-Werte (… `n/a` sonst)“
   wörtlich; beide Felder tragen Bedeutung; keine zweite Schätzung in der Zeile.
   **Capture in `AbstractAgent.compact` VOR `memory.clear()` (:327)** (async-state-safety —
   nach clear ist der Wert weg): `var requestTokens = memory.getLastProviderInputTokens();`
   → als Parameter an den Service (2 Params, s. Inkrement 2).
3. **R-CC-13:** Formel an EINER Stelle: `ChatMessageUtil` private static
   `charsToTokens(int chars) { return chars * 2 / 7; }` — von beiden `estimateTokens`-Overloads
   genutzt (String-Overload behält die ≤5→1-Regel davor). **Compact-Presets raus aus
   `ChatMessageUtil`:** `RenderOptions.compactStage1()/compactStage2()` löschen →
   `ContextTrimComponent.stage1Options()/stage2Options()` (public static, besitzt die Cap-Werte
   9000/6000); `RenderOptions` bleibt generischer Render-Mechanismus (Konstruktor + `defaults()`).
   Trim-Logik (Stufen, Caps, Dedup, letzte User-Message voll) lebt damit vollständig in
   `ContextTrimComponent`. **Kein Verhalten ändert** — Gleiche Zahlen, Characterization-Tests grün.
4. **R-CC-14 — monitor-frei + Return = CompactResult:**
   - `CompactService.compact(String agentName, List<ChatMessage> messages, int budgetTokens,
     String tokenDiagnosis, @Nullable Integer requestTokens, boolean requestIsEstimate)` —
     **kein** `AiMonitor`-Parameter.
   - **`CompactRun`-Record wird gelöscht; `summary` wird 4. Komponente von `CompactResult`**
     (`null` außer COMPACTED). Factory: `compacted(Stats stats, String summary)` (alte
     `compacted(Stats)` weg, d-Liste adaptieren). Re-seed: `result.summary()` (AbstractAgent:338).
   - Interner **log-only Monitor** (privat im Service, kleine anonyme `AiMonitor`):
     `onChatMessage`/`onChatResponse` → `log.debug(...)`, `onStreamingChunk` no-op,
     `onTokenUsage` → `log.debug`. `callBlocking(request, compactCfg, logMonitor)`.
   - **Start-Zeile wandert in `AbstractAgent.compact`** (vor dem Service-Call, `monitor.onTool("Compressing conversation …")` — Inhalt 1:1 wie heute, s. j). Alle 5 Trigger funneln durch `AbstractAgent.compact(monitor)` → **Signatur bleibt**, `PoDelegateTool`/`CompactSessionTool`/`AIChatView`/Auto-Gate **unberührt**.
   - `monitor.onProblem` (FAILED_EMPTY) bleibt in `AbstractAgent.compact` (Bestand).
   - **Konsequenz (kennzeichnen, nicht still):** Header-Counting (`AIChatView.onTokenUsage` →
     `headerBar.addTokenUsage`) bekommt Compressor-Usage nicht mehr — SOLL-konform, Da-Dok-Review.

```mermaid
componentDiagram
    direction LR
    subgraph core-compact
        CompactService -->|stage(messages, budget)| ContextTrimComponent
        CompactService -->|log-only Monitor →| CompactLog
        CompactService -->|callBlocking| ConfiguredChatModel
        ContextTrimComponent -->|RenderOptions (generisch)| ChatMessageUtil

    end
```

der Agent-Layer orchestriert (Guard, Capture, Re-seed, Emission); Plugin sieht nur
`AiAgent.compact()` + `CompactResult` (nun `model`-Package).
