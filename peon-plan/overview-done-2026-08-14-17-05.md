# Compact-Delegation + Mixed Restore — Eclipse Plugin Integration Tests

## 1. Context

ADR-0028 (Compact-Delegation) + Standing Orders Migration bringen neue Compact-Logik:
- `CompactSessionTool` delegiert an `agent.compressContext()`
- `compressContext()` restored `turnContextSupplier` (Mixed Restore)
- `AiPoAgent` (Jon) nutzt `persistentContext` (memory.md, docs/index.md) + `turnContextSupplier` (AGENTS.md, Project-Info)

Die Core-Tests (`AbstractAgentTest`, `CompactSessionToolTest`) validieren die Logik isoliert. Es fehlen **Integration-Tests** mit echtem `PeonAiService` + `CompactSessionTool` im Eclipse-Plugin-Kontext — wo persistentContext, turnContextSupplier, Tool-Delegation und Memory-Zustand gemeinsam getestet werden.

## 2. Design Decisions

- **`PeonAiServiceTest` als Vorlage** — nutzt `AbstractTest`, `MockLlmServer`, `eclipseWriteFile()`.
- **MockLlmServer queueResponses** — pro Test 1-2 Responses (Compressor + ggf. Haupt-Call).
- **Memory-Inspektion nach Compact** — `assertHasUserMessageWith()` auf `agent.getMemory().getCopy()` prüft ob Kontext überlebt.
- **PersistentContext vs TurnContext** — PersistentContext landet im System-Prompt (nicht in Memory!), TurnContext als UserMessage in Memory. Tests prüfen den korrekten Ort.
- **Kein realer Compact-Call** — `compressContext()` direkt aufrufen (als Agent-Methode), nicht über den Tool-Pfad — der Tool-Pfad ist im Core-Test abgedeckt.

## 3. Architecture

```
Test:
  1. eclipseWriteFile() → AGENTS.md, docs/memory.md, docs/index.md
  2. aiService.setActiveAgent(AiPoAgent.NAME) → persistentContext + turnContextSupplier automatisch
  3. aiService.getActiveAgent().setUserContextInformations(orders) → Shim → turnContextSupplier
  4. mockLlmServer.queueResponse(compressedSummary) → Compressor-Stub
  5. aiService.getActiveAgent().compressContext(null) → Compact + Restore
  6. Memory prüfen: TurnContext überlebt, PersistentContext im System-Prompt
```

## 5. Rules & Constraints

- **JUnit 4** (nicht JUnit 5) — wie die bestehenden Tests in `PeonAiServiceTest`.
- **`assumeTrue("Eclipse workspace not available", isWorkspaceAvailable())`** — headless-Mode tolerant.
- **`mockLlmServer.queueResponse()`** — Compressor macht genau 1 Call. Queue muss mindestens 1 Response haben.
- **`@After` cleanup** — `AbstractTest.after()` löscht `eclipseWriteFile()` Dateien automatisch.
- **Timeout** — keine expliziten Timeouts nötig (MockLlmServer ist synchron).
- **PersistentContext ≠ Memory** — PersistentContext wird in den System-Prompt gerendert, NICHT als UserMessage in Memory. Nur TurnContext kommt als UserMessage nach Compact.

## 6. BDD Acceptance

### Scenario: Compact restores turn context for Po agent
**GIVEN** Jon aktiv, `AGENTS.md` + Project gesetzt  
**WHEN** `compressContext()` via Agent aufgerufen  
**THEN** Memory enthält AGENTS.md Content + Project-Info (UserMessage), PersistentContext im System-Prompt (nicht in Memory)

### Scenario: Compact delegates via CompactSessionTool
**GIVEN** Jon aktiv mit Memory-Inhalt + Kontext  
**WHEN** `CompactSessionTool.compactSession()` via ToolService aufgerufen  
**THEN** Agent `compressContext()` wird aufgerufen, Kontext überlebt, Memory enthält Summary

### Scenario: Compact does not duplicate existing context
**GIVEN** Kontext bereits in Memory (vor Compact)  
**WHEN** `compressContext()` aufgerufen  
**THEN** Kontext erscheint nur einmal (contains-Check)

### Scenario: Mixed restore survives (userContext + turnContext via Shim)
**GIVEN** Dev-Agent mit `setUserContextInformations("order1", "order2")`  
**WHEN** Compact via Tool/Agent  
**THEN** "order1" + "order2" sind im Memory (gerestored via Shim) + Summary

## 7. Test Strategy

### Test 1: `test_compactDelegatesToPoAgent()`
**Validiert:** Jon's persistentContext + turnContextSurvive Compact.

```java
@Test
public void test_compactDelegatesToPoAgent() {
    assumeTrue("Eclipse workspace not available", isWorkspaceAvailable());
    
    // GIVEN: Jon aktiv, docs/memory.md + docs/index.md + AGENTS.md existieren
    eclipseWriteFile("docs/memory.md", "# Memory\n- project context");
    eclipseWriteFile("docs/index.md", "# Docs Index\n- feature-x");
    eclipseWriteFile("AGENTS.md", "# Test Specifics\nRule 1");
    aiService.setProject(project);
    aiService.setActiveAgent(AiPoAgent.NAME);
    aiService.getActiveAgent().getMemory().clear();
    
    // Memory füllen (simuliert Konversation vor Compact)
    aiService.getActiveAgent().getMemory().add(UserMessage.from("Talk 1"));
    aiService.getActiveAgent().getMemory().add(AiMessage.from("Reply 1"));
    
    aiService.updateConfig(aiService.getConfig().toBuilder()
            .providerType(AiProvider.OPEN_AI)
            .url(mockLlmServer.getUrl()).build());
    mockLlmServer.queueResponse(AiMessage.aiMessage("WHAT: Compressed summary of conversation"));
    
    // WHEN: Compact via Agent
    aiService.getActiveAgent().compressContext(null);
    
    // THEN: Turn-Context (AGENTS.md + Project) überlebt als UserMessage in Memory
    var memory = aiService.getActiveAgent().getMemory().getCopy();
    assertHasUserMessageWith(memory, "# Test Specifics");
    assertHasUserMessageWith(memory, "Selected project:");
    
    // AND: Summary ist in Memory
    assertHasUserMessageWith(memory, "WHAT: Compressed summary");
    
    // AND: PersistentContext (memory.md + docs/index.md) NICHT in Memory (sondern im System-Prompt)
    // -> systemMessage wird neu gebaut beim nächsten Call, kann hier nicht direkt geprüft werden
    // -> wir prüfen indirekt: System-Prompt enthält persistentContext beim nächsten call
}
```

### Test 2: `test_compactMixedRestore_survives()`
**Validiert:** setUserContextInformations (Shim) → TurnContextSurvive.

```java
@Test
public void test_compactMixedRestore_survives() {
    assumeTrue("Eclipse workspace not available", isWorkspaceAvailable());
    
    // GIVEN: Dev-Agent mit setUserContextInformations
    aiService.setActiveAgent(AiDevAgent.NAME);
    aiService.getActiveAgent().getMemory().clear();
    
    aiService.getActiveAgent().getMemory().add(UserMessage.from("old talk"));
    aiService.getActiveAgent().getMemory().add(AiMessage.from("old reply"));
    
    aiService.getActiveAgent().setUserContextInformations(List.of("order1: be concise", "order2: no filler"));
    
    aiService.updateConfig(aiService.getConfig().toBuilder()
            .providerType(AiProvider.OPEN_AI)
            .url(mockLlmServer.getUrl()).build());
    mockLlmServer.queueResponse(AiMessage.aiMessage("compressed"));
    
    // WHEN: Compact via Agent
    aiService.getActiveAgent().compressContext(null);
    
    // THEN: orders sind im Memory (gerestored via Shim → turnContextSupplier)
    var memory = aiService.getActiveAgent().getMemory().getCopy();
    assertHasUserMessageWith(memory, "order1: be concise");
    assertHasUserMessageWith(memory, "order2: no filler");
    
    // AND: Summary
    assertHasUserMessageWith(memory, "compressed");
    
    // AND: alte Konversation ist weg
    assertHasNoUserMessageWith(memory, "old talk");
}
```

### Test 3: `test_compactNoDuplicates()`
**Validiert:** contains-Check verhindert Duplikate.

```java
@Test
public void test_compactNoDuplicates() {
    assumeTrue("Eclipse workspace not available", isWorkspaceAvailable());
    
    // GIVEN: Kontext bereits in Memory
    aiService.setActiveAgent(AiDevAgent.NAME);
    aiService.getActiveAgent().getMemory().clear();
    
    String existingContext = "already in memory";
    aiService.getActiveAgent().getMemory().add(UserMessage.from(existingContext));
    aiService.getActiveAgent().getMemory().add(AiMessage.from("reply"));
    
    aiService.getActiveAgent().setUserContextInformations(List.of(existingContext));
    
    aiService.updateConfig(aiService.getConfig().toBuilder()
            .providerType(AiProvider.OPEN_AI)
            .url(mockLlmServer.getUrl()).build());
    mockLlmServer.queueResponse(AiMessage.aiMessage("compressed"));
    
    // WHEN: Compact
    aiService.getActiveAgent().compressContext(null);
    
    // THEN: Kontext erscheint NUR EINMAL (contains-Check)
    var memory = aiService.getActiveAgent().getMemory().getCopy();
    var userTexts = memory.stream()
            .filter(m -> m instanceof UserMessage)
            .map(m -> ChatMessageUtil.toString(m))
            .toList();
    
    // Count occurrences
    long count = userTexts.stream()
            .filter(t -> t.contains(existingContext))
            .count();
    assertEquals("Context should appear exactly once (no duplicate after compact)", 1, count);
}
```

## 8. Open Questions

- **PersistentContext in System-Prompt direkt prüfen?** Der System-Prompt ist nicht direkt aus dem Memory auslesbar. **Entscheidung:** Indirekt prüfen via `mockLlmServer.getLastRequestBody()` — die System-Message enthält persistentContext. Kann in Test 1 als AND-Klausel ergänzt werden.
- **Test 4 (Tool-Delegation) nötig?** Core-Tests decken Delegation ab (`testCompactSessionDelegatesToAgent`). **Entscheidung:** Optional — nur wenn Integration-Abdeckung gewünscht.
