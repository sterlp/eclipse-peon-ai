## Rules & Constraints

- Tests use GIVEN/WHEN/THEN with AssertJ assertions (memory rule #1)
- Queue uses default 10s window; test with `UserMessageQueue(250)` constructor for fast batching
- Abort simulation: throw exception from mock model on Nth call

## BDD Use Cases

### Rule 2: FIFO Queue Chaining ✅ (new integration test)

**Test:** `AbstractAgentTest.testQueuedMessagesChainedFifo()`

```
GIVEN an agent with a message queue and a mock LLM returning success responses
WHEN we send "msg1" and then queue "msg2", "msg3" before the first call completes
THEN all three messages are processed sequentially in FIFO order
AND each appears as a separate UserMessage in memory
```

### Rule 4: Abort + Drain with TOOL Message ✅ (new integration test)

**Test:** `AbstractAgentTest.testAbortDrainsQueueWithToolMessage()`

```
GIVEN an agent with queued messages waiting
WHEN the current call throws an exception mid-chain
THEN remaining queue is drained into memory as a single UserMessage
AND monitor.onTool shows "N queued message(s) preserved..."
```

## Notes During Implementation

- `doCall()` adds message to memory *before* the LLM call, so aborting messages are already in memory — drain only handles messages still sitting in queue.
- `ThreadSafeMemory.add()` merges consecutive UserMessages (KV-cache friendly), so drained messages merge with the last user message in memory.
- Queue batching (Rule 1) merges rapid inputs within 10s window if combined length ≤300 chars — tests account for this by using `.contains()` assertions instead of exact matches.
