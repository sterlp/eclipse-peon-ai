# Compact-Delegation (ADR-0028) — Plan

## 1. Context

`CompactSessionTool` currently owns the memory-management logic: it compresses, clears memory, and re-injects standing orders. The owning agent (`AbstractAgent`) already has a `compressContext()` method for auto-compact, but it is unaware of `standingOrders` and only restores `turnContextSupplier`.

Goal: `CompactSessionTool` delegates completely to the agent. The agent's `compressContext()` becomes the single truth for compaction — handling compress, clear, and restore of all context types.

## 2. Design Decisions

- **`ToolLoopRequest.agent`** — new optional field `AiAgent agent;`. Set by `AbstractAgent.doCall()` to `this`. Lets any tool reach back to the owning agent.
- **Delegate-first in CompactSessionTool** — if `agent != null`, call `agent.compressContext(monitor)` and return. Fallback to old inline flow when `agent == null` (legacy/tests).
- **`compressContext()` restores both context types** — after compress + clear, restore `userContextInformations` first (contains-check), then `turnContextSupplier` (contains-check). This ensures the agent's full context survives a compact triggered mid-loop.
- **No standing-orders dependency in tool** — the tool no longer manipulates memory directly; the agent owns it.
- **`AiAgent.compressContext()` already exists** in the interface — no signature change needed. Return type is `ChatResponse`.

## 3. Architecture

```
Agent.call() -> doCall()
                |
                v
        ToolLoopRequest.builder() ... .agent(this).build()
                |
                v
        ToolService.executeLoop() -> tool calls ...
                |
                v
        CompactSessionTool.compactSession()
                | agent != null
                v
        AbstractAgent.compressContext()
                - AiCompressorAgent.call()
                - memory.clear(), systemMessage = null
                - restore userContextInformations (contains-check)
                - restore turnContextSupplier (contains-check)
                - memory.addResult(response)
```

## 5. Rules & Constraints

- **KV-cache safe** — memory manipulation happens after compressor returns; no mid-stream changes.
- **Thread-safety** — `userContextInformations` is already accessed under `synchronized`. `compressContext()` is called from the agent's single call-loop thread (guarded by `AtomicBoolean working`), so no additional sync needed beyond what exists.
- **Contains-check** — `memory.containsUserMessage()` does a text-substring contains. Use it for both restores to skip duplicates (existing pattern in `restoreTurnContext()`).
- **Preserve return contract** — `CompactSessionTool.compactSession()` must still return a String (the summary + preserved text). After delegation, extract from `ChatResponse`.
- **Fallback must be identical** — when `agent == null`, the old inline flow must produce the same result as today.

## 6. BDD Acceptance

### Scenario: CompactSessionTool delegates to agent
**GIVEN** a `ToolLoopRequest` with `agent != null`  
**WHEN** `compactSession()` is called  
**THEN** the agent's `compressContext()` is invoked, memory is cleared and context restored, and the tool returns the summary text

### Scenario: CompactSessionTool falls back without agent
**GIVEN** a `ToolLoopRequest` with `agent == null`  
**WHEN** `compactSession()` is called  
**THEN** the inline compress + clear + resume-message flow runs (standing orders survive via `clearMemory()`)

### Scenario: compressContext restores userContextInformations THEN turnContextSupplier
**GIVEN** an agent with `userContextInformations` = ["AGENTS.md rule"] und `turnContextSupplier` = ["turn item"]  
**WHEN** `compressContext()` is called  
**THEN** memory contains in order: ["AGENTS.md rule", "turn item", AI summary]  
**UND** systemMessage ist null (rebuild at next call)

### Scenario: Restore skips duplicates in both context types
**GIVEN** an agent whose memory already contains text matching a userContextItem or turnContextItem  
**WHEN** `compressContext()` is called  
**THEN** das existierende Item wird NICHT doppelt injiziert (contains-Check)

2. **`testCompactSessionFallbackWithoutAgent()`** — GIVEN agent == null, WHEN compactSession, THEN inline compress + clearMemory + resume-message. Existing tests already cover this well — one explicit test naming the fallback.

### New tests in `AbstractAgentTest`

3. **`test_compressContext_restoresBothContextTypes()`** — GIVEN userContextInformations = ["order1"], turnContextSupplier = ["turnItem"], WHEN compressContext, THEN memory has ["order1", "turnItem", summary] in that order.

4. **`test_compressContext_skipsDuplicatesInBothContexts()`** — GIVEN userContext + turnContext items already in memory, WHEN compressContext, THEN no duplicates.

## 8. Open Questions

- **Should `CompactSessionTool` append the `preserve` parameter after delegation?** Currently the tool returns `summaryText + preservedText`. When delegating, `compressContext()` returns the `ChatResponse` (summary AI message). The tool will append `preserve` to the extracted summary string — same as today. **Decision: Yes, tool still handles `preserve` in return value.**
