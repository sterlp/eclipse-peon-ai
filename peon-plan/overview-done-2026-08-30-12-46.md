## 1. Context — Ziel & SOLL

Per-agent Model-Config als UI: Config-Seite (Preferences) wird **Single Source of Truth** für URL, Key,
Modell, Think, extra JSON body — pro Agent. Chat-UI verliert Modell-Dropdown + Think-Toggle.
Core/UI-Trennung: die Config-Domäne (Record, Speicherung, Auflösung, Identität) lebt in core;
das Plugin ist reine View. Modell-Liste: einmalig pro `ConnectionIdentity`, Cache on success,
Refresh-Button = manueller Refetch, kein Auto-Switch des konfigurierten Modells.

SOLL-Quellen: `docs/advanced-configuration.md` (SOLL-Ergänzung 2026-08-21/28), `docs/model-loading.md` (SOLL 2026-08-28),
`docs/caching.md` R1a/R2 (UI-Gate), `docs/provider.md` R2/R3/R5, `docs/adr/0034-connection-cache-by-identity.md`.

**OUT OF SCOPE (2c):** Cache-Hardcode-Entfernung (Anthropic-Flags/OpenAI-Claude `cache_control` bleiben verhaltenstreu),
GPT/Claude-UI-Beispiele, Cache-Abgleich über Usage-Tokens, Custom-Agent-AGENT.md-Frontmatter-yml, Homepage-Doku (bewusst 2c — PO-Entscheidung 2026-08-29, §9).

## 2. Design decisions

1. **Per-agent Record `AgentModelConfig`** (core, `org.sterl.llmpeon.ai`):
   `record AgentModelConfig(String url, String apiKey, String model, String think, String extraBody)` +
   `static empty()`. `@ToString(exclude = "apiKey")`. NULL/blank Feld = "nicht gesetzt"
   (url/key: erbt Base; model: Provider-Default; think: off; body: keiner).
   **Kein** Temperature-Feld (Scope 2b listet kein Temperature-Widget; die bestehenden
   `llm.devTemperature`/`llm.planTemperature` bleiben flache Base-Felder auf der Advanced-Seite —
   Verhalten unverändert, search/compact behalten die abgeleiteten 0.3/0.2).
2. **Agent-IDs & Key-Schema** (Agent-Prefix laut SOLL, keine zentrale Registry):
   IDs `dev`/`plan`/`search`/`compact`. Keys: `llm.agent.<id>.<field>` mit
   field ∈ `model|url|apiKey|think|extraBody`.
   **Ausnahme Dev-Modell:** `llm.model` (das Base-Modell) bleibt der Dev-Modell-Key —
   "Developer agent always uses the base model" (advanced-configuration.md). Kein zweiter
   Dev-Modell-Key, kein Fallback, kein Datenverlust beim Key-Wechsel.
3. **`LlmConfig` trägt `Map<String, AgentModelConfig> modelConfigs`** (@Default `Map.of()`, immutable)
   + `AgentModelConfig modelConfigFor(String agentId)` (Fehlstelle → `empty()`).
   **Entfernte Felder:** `planModel`, `searchModel`, `compactModel`, `thinkOnString`, `thinkOffString`,
   `planThinkSupported`, `planThinkOnString`, `planThinkOffString` (werden ignoriert beim Load —
   "Sauberer Rebuild: unbekannte Keys ignoriert, keine Migrations-Kette").
   **Bleibt:** `model` (Base/Dev), `thinkSupported` (Base — treibt nur noch Build-time-Thinking
   für Gemini/Mistral + returnThinking-Kontext; Basic-Page-Checkbox unverändert),
   `devTemperature`/`planTemperature`, `sendThinkingEnabled`, Rest.
4. **Think: Wert direkt, kein `effectiveThink`** für Built-ins. Die Factory übernimmt
   `record.think` verbatim in `AgentConfig.think` (gleicher Wertraum wie heute: `""`=off,
   `"true"`=generic-on → `ThinkModelMapping`-Auto, konkretes Level verbatim).
   `ThinkResolver.effectiveThink(...)` bleibt nur für `customAgentConfig(...)` (AGENT.md-Frontmatter, 2c).
   `ThinkModelMapping`/Auto-Modus bleibt intakt (per-request-Auflösung in `effortFor`/`anthropicThinkingType`).
5. **Think-Widget-Formen** (provider.md R5; `ThinkSupport` des **Base-Providers** — Provider bleibt Base-Ebene):
   | Form | Widget | Wert-Mapping |
   |---|---|---|
   | `Boolean` | Checkbox "Think" | an → `"true"` (auto), aus → `""` |
   | `Values` | CCombo `[Off, Auto] + values` | Off→`""`, Auto→`"true"`, sonst verbatim |
   | `FreeString` | TextField | verbatim (`""` = off) |
   | `None` | ausgeblendet | immer `""` (Gemini/Mistral: Build-time, Basic-Page-Checkbox bleibt) |
   | `Unknown` | FreeString (Default, sicherer Fallback) | verbatim |
   **Auto-Eintrag ist Pflicht** (kein Verhalten-Verlust: heutiger Default `supported=true`+leere Strings =
   Auto → Mapping). Mapping-Logik in **non-SWT-Helfer** `ThinkValueSupport` (Plugin, testbar im Test-Modul).
6. **JSON-Body-Widget:** ScrolledText (raw JSON), **sichtbar nur wenn**
   `LlmProviders.of(provider).supportsExtraBody()` (R2-Gate; `ExtraBodyMode != NONE`).
   Sichtbar für PER_REQUEST (OpenAI-Familie) **und** BUILD_TIME (Anthropic). Kein UI-Validieren —
   invalid JSON = Core `ExtraBody.parse` warn+ignore (2a). BUILD_TIME-Body gehört zur
   Connection-Identität (ADR-0034) → Body-Editierung = neue Identität (List-Fetch bei nächstem Need).
7. **Modell-Liste:** Core-Singleton `ModelListCache` (neben `ConnectionIdentity` in `org.sterl.llmpeon.ai`):
   - `cached(id)` → `@Nullable List<AiModel>`
   - `getOrFetch(id, Supplier<List<AiModel>>)` — Cache hit → return; sonst fetch; **null/leere Liste =
     Fehler → null zurück, NICHT gecacht** (on success only); sonst put + return.
   - `refresh(id, fetcher)` — immer fetch; Erfolg ersetzt den Eintrag; **Fehler → alter Eintrag bleibt**;
     returnt das Ergebnis (oder null).
   - `clear()` — Tests.
   Key = volles `ConnectionIdentity` (inkl. buildTimeBody, "gleicher Hash wie Connection-Cache" SOLL).
   Kein Invalidation auf `updateConfig` nötig — Identitäts-Key macht den Cache automatisch korrekt.
8. **Fetch-Triggers:** (1) Seiten-Öffnen (pro Section: Cache check, miss → Job), (2) Refresh-Button.
   **Kein** Live-Refetch beim Tippen in URL/Key/Body (Keystroke-Storm; neuer Fetch erfolgt beim
   nächsten Need — SOLL "einmalig pro Identität"). Fetch läuft in `Job.create`, UI-Update via
   `EclipseUtil.runInUiThread`. Fetch-Aufruf:
   `LlmProviders.of(identity.provider()).listAiModels(EffectiveConnection.of(base, record).buildConfig())`.
9. **Combo-Inhalt:** Liste + konfiguriertes Modell; **konfiguriertes Modell nicht in Liste →
   anhängen + auswählen** (model-loading.md SOLL "wie heute"), **kein Auto-Switch auf erstes Modell**.
   Fetch-Fehler/leere Liste → Combo = nur konfiguriertes Modell (heutiger Fallback B1). CCombo editierbar.
10. **Core/UI-Trennung:**
    - Core: `LlmConfigStore` (key-value: `get(key, def)`/`put`/`remove`), `LlmConfigKeys` (alle Key-Strings,
      Base + Agent — kannonal; Plugin-`PeonConstants`-Konstanten werden 1:1-Alias darauf, Aufrufstellen
      bleiben), `LlmConfigLoader.load(LlmConfigStore)` → kompletter Rebuild (Base + per-agent Records,
      unbekannte Keys ignoriert), `LlmConfigSaver.saveAgentModelConfig(store, agentId, record)`
      (blank Feld → `remove(key)`; Dev-Modell → `llm.model`).
    - Plugin: `EclipseLlmConfigStore` (Adapter um `IEclipsePreferences`, `flush()` bei put/remove),
      `LlmPreferenceInitializer.buildWithDefaults()` delegiert an Loader (DefaultScope-Merge liefert die
      Product-Defaults; Core-Loader hat eigene Fallbacks). `saveModel`/`saveThinkSupported` fallen weg (Inc 5).
11. **Config-Seite = bestehende "Peon Advanced Configuration"** (`AiAdvancedPreferenceView`,
    plugin.xml `org.sterl.llmpeon.prefs.AiAdvanced` — keine plugin.xml-Änderung). Neue Sections als
    Custom-Composites (keine FieldEditors); FieldEditors bleiben für Base-Felder
    (timeout, maxTokens, query/header, debug, realtime, Temperaturen).
    `performOk()`: `super.performOk()` → Sections via Core-Saver speichern → true. Store-Änderung feuert
    den bestehenden Pref-Listener → `AIChatView.applyConfig` → `updateConfig` (clean Rebuild Connections).
12. **Basic-Page bleibt unverändert** (Provider, Base-Modell, Base-URL/Key, `llm.thinkingEnabled`
    (Build-time Gemini/Mistral), sendThinking, Check-Host, GitHub-Login).
13. **Chat-UI-Simplification (Inc 5):** `ActionsBarWidget` verliert `modelCombo` + `btnThink` + alle
    Modell-Liste-Methoden + `onModelChange`/`onThinkToggle`-Callbacks. `AIChatView` verliert
    `reloadModelsIfNeeded`/`loadModelsInBackground`/`showConfiguredModelFallback`/`lastListedConfig`.
    `PeonAiService.setModel`/`withThinkSupported` + `LlmPreferenceInitializer.saveModel`/`saveThinkSupported`
    fallen weg (einzige Caller = Chat-UI, verifiziert per Grep). `AiAgent.isThinkSupported()`/
    `setAgentModelName` bleiben im Interface (Custom-Agent-Frontmatter + 2c).
14. **Search/Compact Think-Widget:** wird gezeigt wie die anderen Sections (uniform, provider-gesteuert,
    leer-Default = heute unverändert). Bewusste Aufweichung von "Search/Compact never think"
    (per-agent-think.md R2 — gilt für den Default null-vs-false). PO-Review-Flag.
15. **Known-Issue-Bug** (Base-URL-Wechsel macht Modell-Auswahl anderer Agenten leer): wird behoben —
    Listen sind pro Identität, kein Auto-Switch, kein Agent-Wechsel-Refetch.

## 3. Architecture — Komponenten & Datenfluss

```
Plugin (View)                                Core (Domain)
─────────────────────────                    ─────────────────────────────
AiAdvancedPreferenceView                     LlmConfigLoader.load(LlmConfigStore) → LlmConfig
  └─ 4× AgentModelConfigSection (Composite)    LlmConfig { base + modelConfigs: Map<id, AgentModelConfig> }
       ├─ url/key Texts                          LlmConfigSaver.saveAgentModelConfig(store,id,record)
       ├─ CCombo Modell + Refresh-Button         LlmConfigKeys (llm.* / llm.agent.<id>.<field>)
       ├─ Think-Widget (Form je ThinkSupport)    AgentModelConfig record
       └─ ScrolledText JSON (nur supportsExtraBody)  EffectiveConnection.of(base, agent) → identity/buildConfig
  performOk → Saver → Store → Pref-Event       ModelListCache (singleton, pro ConnectionIdentity)
AIChatView.prefListener → applyConfig          LlmProvider.listAiModels(buildConfig)
  → PeonAiService.updateConfig (clean Rebuild) ConfiguredChatModel.modelFor(agent) [2a, unverändert]
```

- **Thread-Safety:** Model-List-Fetch in `Job.create`; Combo-Updates nur via `EclipseUtil.runInUiThread`;
  `ModelListCache` thread-safe (ConcurrentHashMap); `ThinkValueSupport` stateless.
- **Deep Module:** Section-Widget kapselt SWT; die Wert-Mappings (Think-Form ↔ String, Sichtbarkeit
  JSON-Widget) sind statische, SWT-freie Methoden → unit-testbar ohne Display.

## 5. Rules & Constraints

- **Build:** Core-Tests `mvn -pl org.sterl.llmpeon.core test`; Plugin-Compile `mvn -o -pl org.sterl.llmpeon,releng/llmpeon-target -am package`;
  **vor Plugin-Testläufen** `eclipseBuildProject` (stale bin/); Core-Änderungen → `mvn clean verify` in core (Tycho/Target Platform).
- **Plugin-Tests:** JUnit 4, OSGi, **keine externen Assertion-Libs**; kein Verlassen auf persistiertem State aus
  früheren Runs (Fixture vor SUT-Build, im `finally` räumen); erster PDE-JUnit-Lauf braucht Workspace-Trust im UI.
- **Core-Tests:** JUnit 5 + AssertJ, GIVEN/WHEN/THEN.
- **Kein Verhalten-Change** an 2a-Mechanik (Connection-Cache, ExtraBody-Merge, per-request Params) — nur aufbauen.
- **Keine Migrations-Kette:** alte Keys (`llm.planModel`, `llm.thinkOnString`, `llm.planThinkEnabled`, …) werden beim
  Load ignoriert (bewusste PO-Entscheidung "Sauberer Rebuild") — **Konsequenz:** bestehende per-agent Modell-/Think-
  Einstellungen alter User gehen beim Update verloren (Base-Model/URL/Key bleiben, die Keys ändern sich nicht).
- **Log OR throw, never both**; Exceptions in UI nicht swallowen (Dialog/Status).
- Agent-IDs `dev|plan|search|compact` sind das stabile Vokabular für Keys und `modelConfigs`.

## 6. BDD Acceptance (Szenario → Test)

**Modell-Liste (ModelListCacheTest, core):**
```
GIVEN die Liste einer Identität wurde erfolgreich geladen      → sameIdentityUsesCacheNoRefetch
WHEN getOrFetch mit gleicher Identität THEN gecacht, kein zweiter Fetch

GIVEN der Fetch schlägt fehl (Exception/leere Liste)           → fetchFailureIsNotCached
WHEN getOrFetch THEN null, kein Cache-Eintrag (UI zeigt configured model)

GIVEN ein gecachter Eintrag                                    → refreshSuccessReplacesCache
WHEN refresh mit Erfolg THEN Cache ersetzt
GIVEN ein gecachter Eintrag                                    → refreshFailureKeepsOldCache
WHEN refresh mit Fehler THEN alter Eintrag bleibt

GIVEN zwei verschiedene Identitäten (URL/Key/Provider/Body)    → differentIdentitiesAreIndependent
WHEN beide geladen THEN separate Einträge
```

**Persistenz (LlmConfigLoaderTest / LlmConfigSaverTest, core):**
```
GIVEN Store mit llm.agent.plan.model=opus, llm.agent.plan.url=…  → loaderRebuildsPerAgentRecords
WHEN load THEN LlmConfig.modelConfigs["plan"] trägt die Werte (Base-Keys wie heute)

GIVEN Store mit unbekanntem/entferntem Key (llm.planModel=…)     → loaderIgnoresUnknownKeys
WHEN load THEN keine Ausnahme, Key wird ignoriert (kein Migrate)

GIVEN record mit blank url/key                                   → saverRemovesBlankKeys
WHEN save THEN Keys entfernt; gesetzt → llm.agent.<id>.* geschrieben

GIVEN Dev-Record mit Modell                                      → saverDevModelUsesBaseKey
WHEN save THEN Key = llm.model (nicht llm.agent.dev.model)

GIVEN load(save(record))                                        → roundtripStable
```

**LlmConfig-Factories (LlmConfigTest, core):**
