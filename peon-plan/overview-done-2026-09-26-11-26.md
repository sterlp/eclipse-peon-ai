## 3. Design-Entscheidungen

1. **`model`-Quelle — additives Feld in `ThreadSafeMemory`** (Entscheidung D **entschieden, sticky** — Jon/Paul 2026-09-26; deckt sich mit dem SOLL-Wortlaut „was das Modell beim letzten Call tatsächlich sah"):
   ```java
   private volatile @Nullable Integer lastProviderInputTokens = null;
   // in BEIDEN addResult-Overloads, nach der usage-Bestimmung:
   if (usage != null && usage.inputTokenCount() != null) lastProviderInputTokens = usage.inputTokenCount();
   // clear() + replaceAll(): lastProviderInputTokens = null;
   public @Nullable Integer getLastProviderInputTokens() { return lastProviderInputTokens; }
   ```
   Semantik: **letzter provider-GEMELDETER** `inputTokenCount()` (Doc-Wortlaut). Antwort ohne
   Usage → vorheriger gemeldeter Wert bleibt (nicht nullen — „letzter gemeldeter"); `n/a` nur,
   wenn nie gemeldet / nach `clear`/`replaceAll`. **Nichts** an der `totalTokenUsed`-Semantik,
   den Gates oder dem Display geändert — reine Beobachtungsgröße.
2. **Ein Format, eine Implementierung** (AGENTS.md): neue Instanz-Methode auf `ThreadSafeMemory`
   (sie besitzt zwei der drei Werte, `estimate` via bestehender `ChatMessageUtil`-Dependency):
   ```java
   /** R-CC-10: Compact-Log-Diagnose — der Suffix wird von ALLEN drei Ereignis-Zeilen angehängt.
       Format fix (Tests asserten gegen die Feldnamen):
       " | memory=<totalTokenUsed>(estimate=<isTokenEstimate>) model=<inputTokenCount|n/a> estimate=<chars×2/7>" */
   public synchronized String tokenDiagnosis() {
       String model = lastProviderInputTokens == null ? "n/a" : String.valueOf(lastProviderInputTokens);
       return " | memory=" + totalTokenUsed + "(estimate=" + tokenIsEstimate + ") model=" + model
               + " estimate=" + ChatMessageUtil.estimateTokens(getCopy());
   }
   ```
   Beispiel: `… | memory=289493(estimate=false) model=80211 estimate=82450`.
   Die drei Call-Sites concatenaten nur — keine doppelte Format-Logik.
3. **Ereignis 1 (Hint-Add):** `ToolService:220` → `onTool("🗜 Compact hint for " + agentName + " added! " + used + memory.tokenDiagnosis())`.
   Die **UserMessage (:221) bleibt UNANGEFASST** — die Diagnose darf in den LLM-Kontext
   (COMPACT_HINT + used) nicht (Context-Pollution); „Log-Zeile" = die onTool-Zeile.
4. **Ereignis 2 (Entry-Log):** `CompactEngine.compact(...)` bekommt einen **zusätzlichen Parameter**
   `String tokenDiagnosis` (vor `monitor`); Engine hängt ihn an der ersten Log-Zeile an
   (nach `thinkingEnabled=…`, vor `\n` + diagnosticBlock):
   ```java
   log.debug("Compact entry: agent={}, …, thinkingEnabled={}{}\n{}", …, thinkingEnabled, tokenDiagnosis, diagnosticBlock(outcome));
   ```
   `AbstractAgent.compact:317` übergibt `memory.tokenDiagnosis()`. Engine bleibt **pure**
   (kennt keinen `ThreadSafeMemory`-Typ — ADR-0056-Info-Hiding bleibt). Existing-Tests erhalten
   `""` als zusätzlichen Argument (mechanisch, 12 Stellen).
5. **Ereignis 3 (Skip):** `CompactSessionTool:44` → `onTool("Compact called but skipped because of small context for " + agent.getName() + agent.getMemory().tokenDiagnosis())`.
   Das Tool-RESULT-String (:45) und die SKIPPED_SMALL-Renderings in `PoDelegateTool:196` /
   `AiAgentStatusModel:76` bleiben **unangeschnitten** (Status-/Result-Zeilen, keine Log-Zeilen).
6. **Nicht im Scope (Scope-Guard):** Gate-Schwellen, Stager, Stager-Stats, `CompactResult`-Record,
   Display/Header, `totalTokenUsed`-Semantik, FAILED_EMPTY-Zeilen, die `monitor.onTool("Compressing
   conversation …")`-Zeile (Engine :72 — UI-Status, eines der drei Ereignisse NICHT), Plugin-Modul,
   Homepage (log-only, kein User-behavior-change), docs (SOLL steht schon).
