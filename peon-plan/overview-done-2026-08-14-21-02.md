# Standing Orders Migration — Plan

## 1. Context

`userContextInformations` (`LinkedHashSet<String>`) in `AbstractAgent` existiert parallel zu `turnContextSupplier` (`Supplier<List<ContextItem>>`). Nach ADR-0028 (Compact-Delegation) restored `compressContext()` den turnContext — das alte `userContextInformations`-Feld ist überflüssig und führt zu Duplizität.

Ziel: `userContextInformations` entfällt zugunsten von `turnContextSupplier`. Alles ist `List<ContextItem>`.

**Warum:** Ein Context-Typ statt zwei — OCP, reduzierte Komplexität, kein Doppel-Restore nach Compact.

## 2. Design Decisions

- **Shim-first Migration** — `setUserContextInformations()` shimmt nach `setTurnContextSupplier()`. Bestehende Caller ändern sich nicht sofort; der Shim übersetzt Strings → `SimpleContextItem` → Supplier.
- **`SimpleContextItem`** für statische Strings — `render()` gibt den String 1:1 zurück. Round-trip sicher für contains-Check.
- **`StandingOrdersBuilder.buildItems()`** — parallele API die `List<ContextItem>` liefert. `build()` bleibt `@Deprecated`.
- **`doCall()` entkoppelt** — nach Shim + Builder-Migration baut `doCall()` keine `standingOrders` (Strings) mehr im Request.
- **Legacy-Fallback in `ToolLoopRequest`** — `standingOrders` + `clearMemory()` bleiben `@Deprecated` für Tests ohne Agent.

## 3. Architecture

```
BEFORE (zwei Welten):
  AIChatView → standingOrders.build() → setUserContextInformations(strings)
                                        → doCall() kopiert nach standingOrders im Request
  JonDelegateTool → setUserContextInformations(orders)
  compressContext() → restore userContextInformations + restore turnContext

NACHHER (ein Weg):
  AIChatView → standingOrders.buildItems() → setTurnContextSupplier(() -> items)
  JonDelegateTool → setTurnContextSupplier(() -> items)
  compressContext() → restoreTurnContext() (nur noch ein Pfad)
```

## 5. Rules & Constraints

- **Round-trip safety** — `SimpleContextItem.render()` gibt den String 1:1 zurück. `getUserContextInformations()` rendert alle Items aus dem Supplier und gibt Strings zurück.
- **Dynamischer Kontext** — `buildItems()` wird pro Turn evaluiert (Selektion ändert sich). Der Supplier kapselt den Builder-Aufruf; kein Cache.
- **Contains-Check** — `restoreTurnContext()` nutzt `memory.containsUserMessage(render())` — substring match. Funktioniert identisch wie bisher mit Strings.
- **Threading** — `turnContextSupplier` ist volatile/safe wie bisher. `setTurnContextSupplier()` setzt den Supplier einmal pro Call.
- **KV-Cache** — Kein Mid-Stream Memory-Manipulation. Restore passiert nach Compress, vor addResult.
- **Deprecated nicht löschen** — `setUserContextInformations()`, `getUserContextInformations()`, `standingOrders` bleiben als `@Deprecated` bis alle Caller migriert sind.

## 6. BDD Acceptance

### Scenario: Shim preserves round-trip
**GIVEN** ein Agent mit `setUserContextInformations(["order1", "order2"])`  
**WHEN** `getUserContextInformations()` aufgerufen  
**THEN** `["order1", "order2"]` zurück (rendered via SimpleContextItem)

### Scenario: compressContext restores only turnContext (kein Doppel-Restore)
**GIVEN** ein Agent mit `turnContextSupplier` (gesetzt via Shim)  
**WHEN** `compressContext()` aufgerufen  
**THEN** memory enthält nur einmal die ContextItems + Summary (kein Doppel-Restore aus altem Feld)

### Scenario: StandingOrdersBuilder.buildItems() liefert ContextItems
**GIVEN** StandingOrdersBuilder mit MessageProvider-Providern  
**WHEN** `buildItems()` aufgerufen  
**THEN** `List<ContextItem>` zurück, gerendert == alter String-Output von `build()`

### Scenario: doCall() baut keine standingOrders mehr
**GIVEN** ein Agent ohne `userContextInformations`  
**WHEN** `doCall()` `ToolLoopRequest` baut  
**THEN** `standingOrders` ist `List.of()` (Default) — Legacy-Fallback inaktiv

### Scenario: JonDelegateTool nutzt turnContextSupplier
**GIVEN** JonDelegateTool dispatchet an Slave mit Orders  
**WHEN** Slave `compressContext()` aufruft  
**THEN** Orders überleben via turnContextSupplier (nicht via altes Feld)

### Scenario: AIChatView Supplier evaluiert pro Turn
**GIVEN** AIChatView mit dynamischem Kontext (Selektion wechselt)  
**WHEN** zwei Calls mit verschiedenen Selektionen  
**THEN** turnContextSupplier liefert jeweils aktuelle ContextItems

## Inkrement Plan

### Inkrement 1: Shim `setUserContextInformations` → `setTurnContextSupplier`
**Ziel:** Alte API funktioniert weiterhin, intern via `turnContextSupplier`. Keine Breaking Changes.

- [x] `AbstractAgent.setUserContextInformations(Collection<String>)`:
  - Wrappt jede String als `SimpleContextItem`
  - Setzt `turnContextSupplier(() -> items)` — **ersetzt** existierenden Supplier
  - Bevoelkert auch legacy `userContextInformations`-Feld fuer doCall() StandingOrders-Kompatibilitaet
- [x] `AbstractAgent.getUserContextInformations()`:
  - Rendert alle Items aus `turnContextSupplier` als Strings zurück
  - Falls Supplier null → leere Liste
- [x] `AbstractAgent.compressContext()`:
  - Entfernt Restore von `userContextInformations` (altes Feld)
  - Nutzt nur noch `restoreTurnContext()` (turnContextSupplier)
- [x] `AgentModeService.call()` Round-trip verifiziert (bestehende Tests)
- [x] Tests: `test_shimRoundTrip()`, `test_shimReplacedByDirectSupplier()`, `test_compressContext_noUserContextRestore()`
- [x] AiAgent Interface: `setUserContextInformations()` + `getUserContextInformations()` → `@Deprecated`
- [x] Full test suite grün (401 core + 29 plugin)

**Betroffen:** `AbstractAgent.java`, `AiAgent.java`, `AbstractAgentTest.java`

---

### Inkrement 2: `StandingOrdersBuilder` → `List<ContextItem>`
**Ziel:** Builder liefert native ContextItems. UI/Tool Caller nutzen neue API.

- [x] `StandingOrdersBuilder`:
  - Neue Interface: `interface ContextItemProvider extends Supplier<List<ContextItem>> {}`
  - `add(ContextItemProvider provider)`
  - `buildItems()` → `List<ContextItem>` (aus allen ContextItemProvider + MessageProvider + oneTimeItems als SimpleContextItem)
  - `build()` + `MessageProvider` → `@Deprecated`
- [x] `AIChatView`:
  - `active.setTurnContextSupplier(() -> this.standingOrders.buildItems())` statt `setUserContextInformations(build())`
- [x] `JonDelegateTool`:
  - `dispatch()`: wrappt orders als `SimpleContextItem`, setzt `setTurnContextSupplier(() -> items)`
- [x] `AgentModeService`:
  - `call()`: wrappt orders als `SimpleContextItem`, setzt `setTurnContextSupplier(() -> items)`
- [x] `UserContext` → `ContextItemProvider` statt `MessageProvider`:
  - `get()` → `List.of(new SimpleContextItem(text))`
- [x] `WorkspaceMemoryTool` → `ContextItemProvider` statt `MessageProvider`:
  - `get()` → `List.of(new SimpleContextItem(memoryText))`
- [x] `AiAgent` Interface: `setTurnContextSupplier()` + `setPersistentContext()` default methods hinzugefügt
- [x] Tests anpassen + grün (380 core + 73/74 plugin, 1 pre-existing failure)

**Betroffen:** `StandingOrdersBuilder.java`, `AIChatView.java`, `JonDelegateTool.java`, `AgentModeService.java`, `UserContext.java`, `WorkspaceMemoryTool.java`, `AiAgent.java`, `PeonAiService.java`, `StandingOrdersBuilderTest.java`
