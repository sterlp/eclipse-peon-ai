## 2. Design-Entscheidungen

### Inc-1 — die 5 Fixes (alle in `org.sterl.llmpeon.core`)

**#1 `StreamingBridge.onError` — `errorRef.set(error)` → `errorRef.compareAndSet(null, error)`**
- Datei: `org.sterl.llmpeon.core/src/main/java/org/sterl/llmpeon/streaming/StreamingBridge.java:196`
- Root-Cause: Nach Cancel speichert `cancelAndRelease()` eine `CancellationException` per
  `compareAndSet(null, …)`. Der Provider feuert danach typ. `onError()` für den getöteten Stream;
  das blinde `set()` **überschreibt** die Cancellation → Caller sieht `RuntimeException` statt
  `CancellationException` → `ApiRetry` RETRYT den gestoppten Call (docs/memory #21).
- Fix: `compareAndSet(null, error)` — der erste Setter gewinnt; Cancel bleibt bestehen.
- Falsch-positiv-Check: Normal-Error-Pfad (kein Cancel, `errorRef` leer) → `compareAndSet` schlägt zu
  → Verhalten unverändert (Test `executeLoop_throws_on_null_response` bleibt grün).

**#2+#3 `SkillPromptFile.readRelativeFile` — Dead-Code-Pfad reparieren + NPE beseitigen**
- Datei: `org.sterl.llmpeon.core/src/main/java/org/sterl/llmpeon/skill/SkillPromptFile.java` (Methode `readRelativeFile`)
- Ist-Bug:
  - `var target = skillDir.resolve(cleaned); if (!Files.exists(target)) target = skillDir.getParent().resolve(cleaned);`
    → für einen skill-qualifizierten Pfad landet `target` **außerhalb** `skillDir`, der Guard
    `if (!target.startsWith(skillDir))` wirft dann **immer** „Path traversal" (False Negative).
  - `skillDir.getParent()` → **NPE** bei parentlosem relativem `skillDir`.
- SOLL (aus den 3 Tests, siehe §6):
  1. Plain-Pfad `file.txt` (relativ zu `skillDir`) → `skillDir/file.txt` (schon grün, bleibt grün).
  2. Qualifizierter Pfad `skills/my-skill/file.txt` bei `skillDir=<base>/skills/my-skill` → `skillDir/file.txt`.
  3. Parentloser `skillDir` + fehlende Datei → IAE „File not found", **nie NPE**.
  4. Path-Traversal (z. B. `../…`) bleibt abgewiesen (IAE „Path traversal").
- Empfohlene Implementierung (Da Mek darf äquivalent wählen, solange die 4 SOLL-Punkte + alle grünen
  Tests grün bleiben) — Resolve gegen `skillDir`, dann gegen **Ancestors** von `skillDir`, bis der
  Kandidat wieder **innerhalb** `skillDir` liegt (normalisiert); Guard = `normalize().startsWith(skillDir.normalize())`:
  ```java
  private Path resolveInSkill(String cleaned) {
      Path base = skillDir.toAbsolutePath().normalize();
      Path plain = base.resolve(cleaned).normalize();
      if (plain.startsWith(base)) return plain;                 // 1. plain
      for (Path anc = base.getParent(); anc != null; anc = anc.getParent()) {
          Path cand = anc.resolve(cleaned).normalize();          // 2. qualifiziert
          if (cand.startsWith(base)) return cand;
      }
      throw new IllegalArgumentException("Path traversal not allowed: " + cleaned); // 4.
  }
  // readRelativeFile: target = resolveInSkill(cleaned); if (!Files.exists(target)) throw IAE("File not found …");
  ```
  `toAbsolutePath()` eliminiert die NPE (kein `getParent()`-Deref auf relativen Pfad mehr).

**#5 `AgentOrder.sort` — zwei orthogonale Duplikat-Fälle, identitätsbasiert + 2× log.warn**
- Datei: `org.sterl.llmpeon.core/src/main/java/org/sterl/llmpeon/agentorder/AgentOrder.java` (Methode `sort`)
- **SOLL (bindend = `docs/agent-ordering.md` R4, vom PO synchronisiert + bestätigt):**
  „first-wins" = **Pattern-Ebene** (R2, ein Agent erscheint einmal). Das seen-Set ist
  **Agent-Identitäts-basiert**, nicht namensbasiert. Zwei **verschiedene** Agent-Instanzen mit
  gleichem Namen kollabieren nicht mehr (das war der Bug: False Negative im Dropdown).
  **Beide** Duplikat-Fälle werden sichtbar geloggt:
  - **Pattern-Ebene:** ein Agent-Objekt matcht mehrere Patterns → erscheint 1× (Gruppe der ersten
    Zeile, R2-Verhalten) + `log.warn` mit **übergehender Zeile + Agent-Name**.
  - **Namens-Kollision:** zwei verschiedene Agent-Instanzen mit gleichem Namen → **beide** erscheinen
    (kein Drop) + `log.warn` mit der **Namens-Kollision**.
- Implementierung (Signatur-Sketch, Da Mek darf äquivalent wählen):
  ```java
  public List<AiAgent> sort(Collection<AiAgent> agents) {
      List<Pattern> effectivePatterns = patterns.isEmpty() ? DEFAULT_PATTERNS : patterns;
      // Namens-Kollision: zwei distinkte Instanzen, gleicher Name → warn (orthogonal zu Patterns)
      agents.stream().collect(groupingBy(AiAgent::getName, counting()))
            .forEach((name, n) -> { if (n > 1)
                log.warn("Agent name collision: {} agents share name '{}' — all kept", n, name); });

      List<AiAgent> sortedAgents = agents.stream().sorted(comparing(AiAgent::getName)).toList();
      Map<AiAgent, Integer> firstMatchLine = new IdentityHashMap<>();   // IDENTITY, nicht Name
      Stream<AiAgent> matchingAgents = IntStream.range(0, effectivePatterns.size())
          .flatMap(lineIdx -> sortedAgents.stream()
              .filter(a -> effectivePatterns.get(lineIdx).matcher(a.getName()).matches())
              .filter(a -> {
                  Integer prev = firstMatchLine.putIfAbsent(a, lineIdx);
                  if (prev != null) {   // Pattern-Ebene: bereits von früherer Zeile beansprucht
                      log.warn("Agent '{}' matched by line {} (already claimed by line {}) — keeping first",
                          a.getName(), lineIdx + 1, prev + 1);
                      return false;
                  }
                  return true;
              }));
      Set<AiAgent> seen = firstMatchLine.keySet();
      Stream<AiAgent> remainingAgents = sortedAgents.stream().filter(a -> !seen.contains(a));
      return Stream.concat(matchingAgents, remainingAgents).toList();
  }
  ```

```
sort(agents):
  byName = group agents by name
  └─ any name with count>1 ──▶ log.warn("…name collision… '{}'")     [Namens-Kollision]
  firstMatchLine = IdentityHashMap<AiAgent,Integer>
```
