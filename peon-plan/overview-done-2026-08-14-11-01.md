# Plan: Split AbstractTest in Unit vs Integration Basen

## 1. Context

`AbstractTest.importProjectIntoWorkspace()` (als `@BeforeClass`) blockiert alle Tests die von `AbstractTest` erben, wenn Eclipse nicht verfügbar ist — auch reine Logik-Tests die keine Eclipse-Features nutzen.

**Problem:** Jeder Test erbt von derselben Base, die Workspace-Setup macht. Tests die nur `assertContains()` oder `mockLlmServer` brauchen, starten trotzdem den Workspace-Import.

**Ziel:** Two-tier Base-Hierarchie:
- `AbstractUnitTest` — pure Helper (Assertions, MockLlmServer)
- `AbstractIntegrationTest extends AbstractUnitTest` — Workspace-Import, Eclipse-Helper

## 2. Design Decisions

- **AbstractUnitTest** enthält alle statischen Assertion-Helper (`assertContains`, `assertHasMessageWith`, etc.) und `MockLlmServer` Lifecycle (`@Before`/`@After`).
- **AbstractIntegrationTest** übernimmt Workspace-Import (`@BeforeClass`), `isWorkspaceAvailable()`, Eclipse-Helper (`eclipseWriteFile`, `eclipseDeleteResource`, `project`).
- **AbstractTest wird gelöscht** — nicht deprecated, direkt entfernt. Alle 6 Tests müssen angepasst werden.
- Tests die kein Eclipse brauchen erben von `AbstractUnitTest`. Tests die Eclipse brauchen erben von `AbstractIntegrationTest`.

## 3. Architecture Decisions

- Package bleibt `org.sterl.llmpeon.test` — beide Bases im selben Package.
- `MockLlmServer` Lifecycle (start/stop) gehört in `AbstractUnitTest` — auch Integration-Tests brauchen den Mock-Server.
- `toDelete` tracking + cleanup gehört in `AbstractIntegrationTest` — nur Eclipse-Tests schreiben Dateien.

## 4. Affected Files

### Neue Dateien
- `org.sterl.llmpeon.test/src/org/sterl/llmpeon/test/AbstractUnitTest.java` — pure Helper
- `org.sterl.llmpeon.test/src/org/sterl/llmpeon/test/AbstractIntegrationTest.java` — Eclipse Workspace + Integration

### Geänderte Dateien (extends anpassen)
- `PeonAiServiceTest.java` → `extends AbstractIntegrationTest`
- `EclipseWorkspaceWriteFileToolTest.java` → `extends AbstractIntegrationTest`
- `JdtUtilDiskPathTest.java` → `extends AbstractIntegrationTest`
- `StandingOrdersBuilderTest.java` → `extends AbstractIntegrationTest`
- `EclipseWorkspaceReadFileToolTest.java` → `extends AbstractIntegrationTest`
- `EclipseCodeNavigationToolTest.java` → `extends AbstractIntegrationTest`

### Gelöschte Dateien
- `AbstractTest.java` — wird durch die zwei neuen Bases ersetzt

### Unverändert
- `UiCommandTest.java` — erbt von nichts (bleibt so)
- `AiAgentStatusModelTest.java` — erbt von nichts (bleibt so)
- `EclipseWriteValidatorUnitTest.java` — erbt von nichts (bleibt so)
- Alle Core-Module-Tests (`org.sterl.llmpeon.core`) — betroffen nur Plugin-Test-Modul

## 5. Rules & Constraints

- **Plugin-Test-Modul nutzt JUnit 4** — keine AssertJ, keine JUnit 5. OSGi classpath constraints.
- **`assumeTrue("Eclipse workspace not available", isWorkspaceAvailable())** bleibt in Integration-Tests als individual Test-Guard (nicht in @BeforeClass global).
- **MockLlmServer Lifecycle** — `@Before start()`, `@After stop()` — in AbstractUnitTest.
- **toDelete tracking** — nur AbstractIntegrationTest (Eclipse-Datei-Cleanup).
- **Statische Helper** bleiben `static` — nicht an Instanz gebunden, damit sie ohne Base-Vererbung nutzbar sind.

## 6. BDD Acceptance

### Scenario: AbstractUnitTest ohne Eclipse startbar
```
GIVEN AbstractUnitTest (keine Eclipse-Imports)
WHEN Tests die nur AbstractUnitTest erben in Maven/Tycho laufen
THEN Tests starten ohne Eclipse Workspace Setup
```

### Scenario: AbstractIntegrationTest importiert Workspace
```
GIVEN AbstractIntegrationTest mit @BeforeClass
WHEN Eclipse Workspace verfügbar
THEN project ist gesetzt und Workspace importiert
WHEN Eclipse Workspace nicht verfügbar
THEN Tests werden via assumeTrue skipped
```

### Scenario: MockLlmServer Lifecycle in AbstractUnitTest
```
GIVEN ein Test der AbstractUnitTest erbt
WHEN @Before ausgeführt
THEN mockLlmServer.start() aufgerufen
WHEN @After ausgeführt
THEN mockLlmServer.stop() aufgerufen
```

### Scenario: Eclipse-Helper nur in AbstractIntegrationTest
```
GIVEN AbstractIntegrationTest
WHEN eclipseWriteFile() aufgerufen
THEN Datei im Workspace geschrieben + toDelete tracking
WHEN @After ausgeführt
THEN alle toDelete-Dateien gelöscht
```

### Scenario: Alle bestehenden Tests bauen grün
```
GIVEN alle 6 Tests auf AbstractIntegrationTest umgestellt
WHEN mvn clean verify
THEN Build grün, alle Tests passen, AbstractTest gelöscht
```

### Test Mapping
- Manuelle Verifikation: `mvn clean verify -pl org.sterl.llmpeon.test` — alle Tests grün
- Manuelle Verifikation: Headless Test (ohne Eclipse) — Unit-Tests laufen, Integration-Tests werden skipped

## 7. Test Strategy

- Keine neuen Tests nötig — Existing Tests dienen als Validierung.
- Nach dem Refactoring: Full build + Test run um sicherzustellen dass nichts bricht.
- Headless-Test (optional): Tests ohne Eclipse ausführen → Integration-Tests sollten skipped werden.

## 8. Open Questions

- **Keine** — Design ist klar.

## Implementation Increments

### Increment 1: AbstractUnitTest erstellen + alle Tests anpassen

**Neue Datei:** `org.sterl.llmpeon.test/src/org/sterl/llmpeon/test/AbstractUnitTest.java`
```java
package org.sterl.llmpeon.test;

import static org.junit.Assert.assertNotNull;
import static org.junit.Assert.assertTrue;

import java.util.Collection;
import java.util.Optional;
import java.util.stream.Collectors;

import org.junit.After;
import org.junit.Before;
import org.sterl.llmpeon.mock.MockLlmServer;
import org.sterl.llmpeon.shared.ChatMessageUtil;

import dev.langchain4j.data.message.ChatMessage;
import dev.langchain4j.data.message.UserMessage;

public abstract class AbstractUnitTest {
    
    protected final MockLlmServer mockLlmServer = new MockLlmServer();
    
    @After
    public void after() {
        mockLlmServer.stop();
    }
    
    @Before
    public void before() {
        mockLlmServer.start();
    }
    
    // === Statische Helper (aus AbstractTest übernommen) ===
    
    public static void assertContains(String value, String expected) {
        assertNotNull("Expected to find " + expected, value);
        assertTrue("Expected:\n" + value + "\nto contain:\n" + expected, value.contains(expected));
    }
    
    public static void assertHasNoUserMessageWith(Collection<ChatMessage> messages, String content) {
        var textMessages = messages.stream()
            .filter(m -> m instanceof UserMessage)
            .map(m -> ((UserMessage)m).singleText())
            .toList();
        assertHasNoMessageWith(textMessages, content);
    }
    
    public static void assertHasNoMessageWith(Collection<String> textMessages, String content) {
        var match = textMessages.stream().filter(m -> m.contains(content)).findAny();
        assertTrue("Found match: \n" + content + "\nin:\n" + match.orElse(null), match.isEmpty());
    }
    
    public static void assertIsEmpty(Optional<?> v) {
        assertTrue("Expected optional to be empty", v.isEmpty());
    }
    
    public static void assertIsPresent(Optional<?> v) {
        assertTrue("Expected optional to have a value", v.isPresent());
    }

    public static void assertHasUserMessageWith(Collection<? extends ChatMessage> messages, String content) {
        var textMessages = messages.stream()
            .filter(m -> m instanceof UserMessage)
            .map(m -> ChatMessageUtil.toString(m))
            .toList();
        assertHasMessageWith(textMessages, content);
    }
    
    public static void assertHasMessageWith(Collection<String> textMessages, String content) {
        var match = textMessages.stream().filter(m -> m.contains(content)).findAny();
        assertTrue("Could not find: \n" + content + "\nin:\n" + textMessages.stream().collect(Collectors.joining("\n")), match.isPresent());
    }
}
```

**Build:** `mvn clean verify -pl org.sterl.llmpeon.test -am` — baut grün (keine Tests erben noch davon, aber Klasse compiliert)

### Increment 2: AbstractIntegrationTest erstellen

**Neue Datei:** `org.sterl.llmpeon.test/src/org/sterl/llmpeon/test/AbstractIntegrationTest.java`
```java
package org.sterl.llmpeon.test;

import static org.junit.Assume.assumeTrue;

import java.io.File;
import java.util.HashSet;
import java.util.Set;
import java.util.concurrent.CountDownLatch;

import org.eclipse.core.resources.IProject;
import org.eclipse.core.resources.IProjectDescription;
import org.eclipse.core.resources.IWorkspace;
import org.eclipse.core.resources.IncrementalProjectBuilder;
import org.eclipse.core.resources.ResourcesPlugin;
import org.eclipse.core.runtime.CoreException;
import org.eclipse.core.runtime.IPath;
import org.eclipse.core.runtime.NullProgressMonitor;
import org.junit.After;
import org.junit.BeforeClass;
import org.sterl.llmpeon.parts.tools.EclipseWorkspaceWriteFileTool;

public abstract class AbstractIntegrationTest extends AbstractUnitTest {
    
    protected static IProject project;
    private final EclipseWorkspaceWriteFileTool writeTool = new EclipseWorkspaceWriteFileTool();
    private final Set<String> toDelete = new HashSet<>();
    
    @Override
    @After
    public void after() {
        super.after();
        
        writeTool.setCurrentProject(project);
        toDelete.forEach(f -> writeTool.eclipseDeleteResource(f));
        toDelete.clear();
    }
    
    protected void eclipseWriteFile(String file, String content) {
        writeTool.setCurrentProject(project);
        writeTool.eclipseWriteFile(file, content);
        toDelete.add(file);
    }
    
    protected void eclipseDeleteResource(String file) {
        writeTool.setCurrentProject(project);
        writeTool.eclipseDeleteResource(file);
        toDelete.remove(file);
    }

    @BeforeClass
    public static void importProjectIntoWorkspace() throws Exception {
        assumeTrue("Eclipse workspace not available", isWorkspaceAvailable());

        try {
            importProject(new File("./").getCanonicalFile());
        } catch (CoreException e) {
            assumeTrue("Cannot import project (likely Maven/Tycho workspace overlap): " + e.getMessage(), false);
        }
    }
    
    protected static void importProject(File projectDir) throws Exception {
        final var latch = new CountDownLatch(1);

        IWorkspace workspace = ResourcesPlugin.getWorkspace();
        IProjectDescription desc = workspace.loadProjectDescription(
                IPath.fromOSString(new File(projectDir, ".project").getAbsolutePath()));

        desc.setLocation(IPath.fromOSString(projectDir.getAbsolutePath()));

        project = workspace.getRoot().getProject(desc.getName());
        workspace.run(monitor -> {
            if (project.exists()) {
                project.delete(false, true, monitor);
            }
            project.create(desc, monitor);
            project.open(monitor);
            project.build(IncrementalProjectBuilder.FULL_BUILD, new NullProgressMonitor());
            latch.countDown();
        }, new NullProgressMonitor());

        latch.await();
    }
    
    protected static boolean isWorkspaceAvailable() {
        try {
            ResourcesPlugin.getWorkspace();
            for (IProject p : ResourcesPlugin.getWorkspace().getRoot().getProjects()) 
                p.open(new NullProgressMonitor());
            return true;
        } catch (IllegalStateException | CoreException e) {
            return false;
        }
    }
}
```

**Build:** `mvn clean verify -pl org.sterl.llmpeon.test -am` — baut grün
